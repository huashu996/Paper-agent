# 红色批注/修改指令逐项闭环工作流

当用户提供带红字、批注、修订说明或单独的“Codex 执行指令”文档，并要求修改最新版论文时，执行本流程。它叠加于 `revision_only + word_layout`；若要求可提交/送审版，使用 `submission`。

## 1. 冻结对象与排版合同

1. 按修改时间、文件名和用户措辞只读确认“最新版”，复制到唯一工作副本；绝不在来源文件上覆盖。
2. 读取用户此前对同一论文确认的学校模板和覆盖参数。排版合同对后续所有内容修改持续生效，内容优化不得破坏版式。
3. 冻结并计数图像关系、媒体文件、表格、展示公式、书签、超链接、分节、EndNote `EN.CITE`/`EN.REFLIST`、修订和批注。
4. 建立基线 PDF/全页渲染。图文对应必须以“图号—题名—章节锚点—媒体哈希”核验，不能只比媒体总数。

## 2. 提取指令台账

逐项提取：ID、位置、问题、动作类型、证据要求、风险、作者决定和需复算数据。每项只允许以下闭环状态：

- `完成`：正文、公式、图表或版式已修改并验证。
- `已修订，待补证`：缺少日志、标定、统计或代码测试；正文已改为证据边界，不虚构结果。
- `待作者提供依据`：需要 EndNote Group、原始数据或不可推断的作者选择，禁止擅自完成。

作者明确给出的名称、阈值、硬件、平台数量、传感器类型和实验方式优先于旧稿。

## 3. 证据优先修改

1. 数据问题：从表格原数复算均值、比例、成功集和增益；记录公式与分母，禁止只改叙述不改摘要/结论。
2. 公式/实现问题：以实际代码为准核对状态维数、残差来源、插值模型、收敛阈值和协方差含义。实现不存在的统计模型必须降级为确定性正则化或局限。
3. 文献问题：优先官方出版页、DOI、代码仓库 commit；没有已确认 EndNote Library/Group 时冻结 CWYW，不插入伪引用。
4. 图形文字错误：先识别真实媒体格式。可编辑矢量源存在时直接修改矢量文字和回退流；不得为改字把清晰矢量图整体栅格化。
5. 批量修改集中写入，同一对象两次失败后换稳定实现；禁止多轮全稿重排掩盖根因。

## 4. 版式同步约束

- 修改正文后立即检查受影响页的分页、标题与下段同页、正文 `keepNext/keepLines`、孤行和异常空白页。
- 图、图题、表、表题、表注分别处理；不得把居中、缩进或分页属性传播到正文。
- 修改任何 Word 表格对象前必须读取并执行[Word 表格对象分类与变更阻断闸门](table-object-classification-gate.md)：先建立基线注册表和允许修改白名单，严禁遍历全部 `<w:tbl>` 统一格式。用户最后确认的线宽覆盖规则只应用于语义数据表；公式编号、封面、图片拼版和题注/表注布局表默认无边框并保持基线。数据表无竖线、无逐数据行横线、无双线，表级与单元格级不得重复画同一边。
- 参考文献每一条设置“同段不拆页”，避免最后一行单独跨页；其余格式服从学校模板或已确认 EndNote Style。
- 目录、图表目录和交叉引用只在最终分页稳定后更新一次。

## 5. 安全更新 Word 域

最终使用 Word 本体更新目录、`SEQ`、`REF` 和 `PAGEREF`，显式跳过所有 `ADDIN EN.` 域。更新后必须复核：

- EndNote 域数量与代码哈希等于来源文档；
- 目录页码与实际章节首页一致；
- 题注未出现双编号；
- Word 能无修复提示打开并导出 PDF。

Word 规范化保存可能删除 `nil` 边框上无意义的 `w:sz="0"`，此时 `w:val="nil"` 且无字号与 `nil + 0` 视为等价；不得误判为竖线回归。

## 6. 提交级验收

1. 全文导出 PDF 并检查全部页面；再以原始分辨率复核目录、每章首页、长公式、宽表、修改图、参考文献末页和文后成果页。
2. 结构审计至少覆盖：ZIP CRC、段落/表格/图像关系、缺失媒体、展示公式段数、书签、超链接、修订、批注、红字和用户指定术语残留。
3. 表格按对象类型分别验收：数据表逐表核对三条主线与垂直边；公式、封面、图片和题注布局表逐表核对无非预期可见边框；白名单外对象相对基线的文字、边框和几何签名必须零差异。参考文献逐条核对 `keepLines`；摘要研究内容段核对篇幅平衡。
4. 输出最终 DOCX 和“逐项修改记录”，台账中每个 ID 必须有状态和结果；所有待补证项集中列出所需材料。
5. 只有结构检查通过且最终 PDF 可见质量通过，才标记为可提交版本。
