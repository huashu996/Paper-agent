## 规范层级与唯一执行口径

按 `用户当前要求 → 已确认参数/骨架/冻结项 → 本节冲突矩阵 → 对应专项章节 → 通用构建建议` 执行。后文保留的场景规则用于补足细节，不得重新解释本节已经统一的口径。若同一要求在多处重复，执行最具体且不降低质量的一处，不叠加重复流程。

| 主题 | 唯一执行口径 |
|---|---|
| 执行范围 | 继承主 `SKILL.md` 的 `fast_local`、`standard`、`submission`。局部微改不启动整页重建或全稿审计；新建整页、主拓扑改变、参考图复刻和公式批处理使用 `standard`；送审前整稿检查使用 `submission`。 |
| 参数确认 | 新建整页、重构主拓扑、改变比例或公式类型时确认完整适用参数。`fast_local` 继承目标页现有页面、比例、字体、配色和风格，只确认本次改变项；继承值不足以安全完成时才暂停询问。 |
| 风格选择 | 顺序固定为：用户明确要求/参考图 → 用户模板或既有页 → 内置五页模板语义路由 → 适用时三栏递进式 → 仅在均不适用且方案差异实质影响结果时二选一。不得无条件强迫用户重复选择。 |
| 图体比例 | 页面比例、主图体比例、复杂模块比例分别冻结。A4 纵向不等于填满页面；保持原图比例时只允许最大等比缩放和整体平移。 |
| 骨架审核 | 从文字新建整页或改变主拓扑时必须先交静态 SVG 骨架；参考图本身可作为骨架；只改字、移动或连接少量对象且不改主拓扑时免骨架。 |
| 账本与审计 | 新建整页和复杂重构建立对象、文字、连接器、视觉账本及原生审计清单。`fast_local` 只建立被触及对象快照与页级清单，并运行对应的局部检查，不生成无关全页/全稿账本。 |
| 审查上限 | 首次完整保存后进行一次合并审查；发现真实问题时集中修正一次，再做一次定向审查。第二次审查后停止自动返工并如实记录残留问题，除非用户明确授权继续。构建前预检失败和脚本未写入/已回滚不计为内容审查。 |
| 质量门槛 | 执行档位只缩小检查范围，不放宽目标 PPT 隔离、内容保真、公式类型、可编辑性、文本安全距离、零溢出/零碰撞、连接器锚点、箭头几何和未授权对象不变等标准。 |

所有详细章节必须按该矩阵解释。不得用重复流程、额外审查或未授权的参数重确认扩大任务。

## 原生对象优先与快速生成

适用于可编辑 PPT 新建页、参考图重建和原页修改。提速来自稳定原生对象、批量生成和复用检查结果；保持用户指定的内容、模板、颜色、字体、图体比例和页面动作。本节优先于本文件无条件 SVG 化、逐对象预检及反复内存重画要求；用户明确指定 SVG 或要求直接使用某素材时遵从用户。

### 对象选型

| 对象 | 首选实现 | 边界 |
|---|---|---|
| 矩形、圆、圆角框、宽箭头、色块 | `Shapes.AddShape` 或已验证库的原生预设形状 | 模块文字写入所属 shape；不用图片或手工自由路径模拟已有预设 |
| 模块之间的直线、折线、箭头 | 单个 `Shapes.AddConnector`，连接真实锚点 | 先对齐再连接；不使用多段线拼接，不复制旧连接器后断开重绑 |
| 弧线、轨迹、回环、曲线箭头 | 优先复用现有原生曲线；预设 Arc 能准确表达时用 Arc，否则用单个 `BuildFreeform → AddNodes → ConvertToShape` 原生自由曲线 | 显式控制点与箭头头型；记录实际端点，不能把自由曲线声称为自动绑定的连接器 |
| 分隔线、刻度、图例线等非连接关系 | 已验证的单个原生线对象或原生自由路径 | 登记为装饰线，避免被连接器审计误判；当前审计器不能区分时直接复用已验证的自由路径 |
| 简单图标 | 已有原生对象或少量原生形状组成的独立图标 | 保持轮廓与语义；复杂矢量轮廓才用单独 SVG，不为 SVG 化增加描摹流程 |
| 照片、机器人实物、点云、复杂场景 | 按主体抠出的独立图片 | 可分离的外部文字、框体和箭头仍用原生对象；不把整页或整组截图当成可编辑重建 |

### 兼容性与失败处理

- **禁止把 `p:cxnSp` 的预设几何直接替换成未经验证的 `a:custGeom`。** 此类曲线实现即使通过 XML 检查，也可能使 PowerPoint 拒绝打开和导入。自由曲线用 Office 原生 API 或已经实际打开验证的普通自由形状 `p:sp` 实现；XML 合法不等于 PowerPoint 兼容。
- 本机同版本环境已验证的对象实现直接复用。只有新增几何实现、显著改变 Arc 形态、运行时变化或出现兼容性证据时，才对对应对象做一次最小原生打开/渲染测试；不为每条同类曲线重复测试，不复制整页来试一个对象。
- 同一对象实现首次发生原生打开/导入失败时，先定位问题对象，切换到已验证的原生实现并复测一次；禁止在权威文件中连续盲改 XML。切换仍失败时保留可恢复状态并说明具体阻断，不降级为截图冒充可编辑对象。

### 批量构建、检查与计时

1. 已明确的目标文件、字体、模板和页面动作直接沿用；参考图本身作为骨架。复用当前任务所需组件和同一份对象数据，不重新开发通用框架或加载无关工作流。
2. 同一批完成复杂图抠图、原生形状/文本/路径构建及坐标排版。仅在确有新兼容性风险时制作最小测试包；已验证后端直接生成目标页，不额外进行整页生成—导入往返。
3. 含公式时保留必要的基础包打开与视觉检查，然后批量调用内置公式流水线；公式后只检查新增公式及最终版面。其余检查共用一次原生渲染和一次对象回读，采用已有“一次合并审查、一次必要集中修正、一次定向复核”上限。
4. 检查器误报先核对实际对象和适用范围，不改动正确图形来迎合脚本。Office 公式的 `mc:AlternateContent` 中 Choice 与 Fallback 是同一个显示对象的替代表示，不能合计成两个对象；以 PowerPoint 对象数、非空 MathZone 和最终渲染核验。自由曲线若不在直连接器扫描范围，单独回读路径、端点和箭头，不能漏检。替代检查须覆盖同一指标并留下证据，不得静默排除失败项后宣称全通过。
5. 原生公式可能仍由 Office 使用数学字体；普通文字字体与公式字体分别回读。不要反复设置普通字体企图强制改变数学引擎字体，也不能声称未生效的字体设置已经生效。
6. 在现有任务日志记录“准备、素材、构建、公式、检查、排错”的开始/结束时间；不另建计时系统。普通单页且素材可用、实现已验证时以 **3–5 分钟**为目标；多处复杂抠图或公式任务按复杂度安排，约 **5–8 分钟**为工作目标而非完成保证。排错超过约 1 分钟时及时说明具体原因并收敛方案；不得为赶时间降低可编辑性、忠实度或检查标准。

## 用户确认默认风格：三栏递进式学术系统图

用户未指定另一参考图、模板或视觉语言，且任务属于研究框架、技术路线、系统总览、章节关系或平台—方法—成果概览时，采用本节；参考图忠实复刻仍以参考图为硬标准。

1. **内容先压缩。** 先建立“对象/平台 → 统一模型或方法 → 研究内容递进 → 最终输出”的短标签账本。普通模块默认 `1–2` 行，只保留名称、关键词和必要关系；正文式解释移到图题、图注或正文。保留逻辑、数据、公式和结论，不等于保留每句原文。忠实复刻未经授权不得删改参考图可见文字。
2. **骨架默认三栏。** 主图体优先采用约 `3:2` 的横向构图：左栏放平台、对象或输入，中栏放统一建模、方法或关键处理，右栏放章节/研究内容递进和最终成果；栏间只保留两枚醒目的阶段箭头。三栏外框等高、顶边对齐、栏间距一致，分区标题置于左上角，内部沿共享轴和规则网格排布。
3. **层级与配色。** 一级核心模块用深洋红或等效高对比主色；二级说明模块用浅粉/近白底；阶段箭头用浅青；最终输出用蓝青色横条；虚线分区边框使用克制的深蓝灰。背景默认白色或透明，不把查看器黑底误判为参考图底色。颜色必须表达层级，不能让所有框同等醒目。
4. **语义图标优先。** 设备、通信、输入数据、结果和计算平台使用轮廓清晰、风格统一的语义图标或逐个 SVG；存在可靠图标时，不用低识别度的基础形状拼装代替。图标用于一眼识别，不承载正文解释。
5. **字体固定下限。** 中文使用宋体/SimSun；A4 论文图保持 `10–14 pt`，一般模块 `10–12 pt`、分区标题 `12–14 pt`。不得为塞字降到 `10 pt` 以下；先压缩措辞、扩大框体、重分列宽或重做骨架。
6. **连接关系克制。** 跨栏关系由两枚大箭头表达；栏内只保留证明逻辑所必需的连接。禁止蜘蛛网式连线、重复箭头、穿字路径和无语义装饰线。读者应能在 `3` 秒内识别“左 → 中 → 右 → 最终输出”的主阅读路径。
7. **视觉审核先于几何审核。** 先检查阅读路径、主次层级、留白、图标识别度、光学平衡和整体构图，再检查越界、碰撞、锚点、对象数、可编辑性和 OOXML。仅“没有越界、对象可编辑、脚本通过”不能判定设计合格。
8. **错误骨架直接重排。** 骨架出现长段文字、比例失衡、层级不清或连线过密时，废弃该骨架并按本节重排；禁止继续机械缩放、逐框挤压或在错误底稿上反复打补丁。

质量阻断项：正文式长句进入普通模块；孤字或孤 token 行；语义图标不可辨认；三栏主轴、栏宽或间距明显失衡；所有模块视觉权重接近；主阅读路径需要追踪大量细线；字号低于用户下限；用整体机械缩放代替重新排版。

## 局部微修改快速路径与常见失败防护

本节适用于已有 PPT 中单页、至多 `10` 个对象的增删、改字、移动、缩放或连接调整，高于后文面向新建整页和复杂复刻的重型流程。此类任务以 `3` 分钟左右完成一次可靠修改为执行目标；安全或真实阻断可延长，但不得用不相关审计主动扩大任务。

1. **先确认页，再写入。** 开始时只读核对唯一目标路径、当前页数、用户所指页面的缩略图和稳定对象名。历史页码、上一轮页码和文件名中的页码都不能替代当前检查。用户纠正页码后，立即废弃旧页全部假设、脚本参数和审计结果；确认新页面拥有预期对象后才允许写入。
2. **最小改动，不做工程化扩张。** 先建立 UTF-8 `local-edit-manifest.json`，字段至少包括 `target_pptx`、`slide_index`、`authorized_objects`、`operations`、`inherited_parameters`、`must_remain_unchanged` 和写入前快照。优先复用 `scripts/figure/` 的固定能力，不为同类操作反复重写临时脚本；现有能力不覆盖时，只允许一个由清单驱动的最小 COM 写入器。不得为两个框或两条线启动模板映射、整稿结构盘点、全页重建、通用幂等框架或整份 PPTX 账本。微修改只保留一份即时备份、一个页级对象清单和一次页级渲染。
3. **预检与写入严格分离。** 预检阶段验证页面、对象、连接模板、只读状态和授权范围，但不移动、复制、删除、改字或重连任何对象。写入前保存全部被触及对象的坐标、尺寸、文字、格式、连接端点、箭头样式和 Z 序；写入脚本发生解析、名称、对象、校验或保存异常时必须恢复快照，不得把未保存的部分修改留在当前 PowerPoint 会话中。
4. **不要用通用脚本制造新风险。** 能直接复制一个框、创建一条线并排齐时，不为重复执行、跨页泛化或未来场景构造动态数组和复杂循环。脚本参数先用只读小样验证；数组解析、动态属性或对象命名出现一次错误后，先修正并重新预检，禁止在已有部分修改的会话中盲目重跑。
5. **中文单行文字采用组合判据。** `TextRange.BoundHeight` 在宋体中文中可能按字体度量返回接近两行的高度，不能单独作为溢出阻断。单行框同时检查 `TextRange.Lines.Count`、`BoundWidth` 与可用宽度、形状内边距和最终渲染；字体不得低于用户下限。空间不足时优先扩展授权容器与总线、重新分配同级宽度或缩短文字。
6. **新箭头必须重新创建。** 禁止复制旧连接器、执行 `BeginDisconnect/EndDisconnect` 后再绑定新对象。旧连接器会携带 `FlipH/FlipV`、路由、内部起止方向和箭头状态，逻辑端点正确仍可能在视觉上反向。应先让源节点与目标框共轴，再用 `Shapes.AddConnector` 新建一条原生直线或用户要求的单对象折线，按“源节点 → 目标框”顺序连接真实锚点，显式设置 `BeginArrowheadStyle=None`、`EndArrowheadStyle=目标样式`，并保持线宽、颜色和 Z 序与同级连接器一致。
7. **箭头审核不能只看连接状态。** 除 `BeginConnected/EndConnected`、连接对象名和站点外，必须在最终页渲染中确认箭头头部实际位于目标端、朝向目标框、未落在总线端、未反转、未穿字且与同级箭头一致。端点身份检查通过不能替代视觉方向检查。
8. **只审授权页。** 微修改完成后只检查授权页面、被修改对象、相邻对象和对应连接器。只有本次写入前即时创建的备份才能作为整稿差异基线；备份生成后若用户或 PowerPoint 已继续修改文件，基线立即失效。禁止用陈旧基线比较全包，也禁止把 ZIP 条目重排、保存归一化、关系编号变化或其他会话改动解释为本次修改越界。
9. **时间异常立即收敛。** 微修改超过约 `3` 分钟时，先向用户说明具体阻断，再回到直接路径；不得通过增加审计、重写通用脚本或扩大比较范围消耗更多时间。脚本失败应报告“未写入/已恢复/当前页面状态”中的真实一种，不得含糊继续。

典型“增加一个输入模块”任务的固定顺序为：只读确认当前页与现有同级框 → 冻结目标页 → 复制同级框体并改内部文字 → 新建节点和原生连接器而非复制连接器 → 同级框体排齐并按需扩展同一容器与总线 → 保存一次 → 只渲染该页并核对文字、箭头方向和边界。不得把该顺序扩展成整稿工程。

## 4.2/4.3 方法框图失败复盘与防复发闸门

本节来自连续时间轨迹与滑窗优化框图的实际返工，适用于所有论文方法图的新建、重绘和局部修订，是通用规则在该类图上的失败关闭补充。交付前必须逐项核对，不能以“对象可编辑”或“审计脚本通过”替代最终渲染中的视觉合格。

| 已发生的错误 | 后续强制规则 |
|---|---|
| 把 A4 纵向母版当成必须填满的图体比例，导致原图被压扁或拉长 | 页面比例、主图体比例和复杂模块比例分别冻结。保持原图比例时，只允许在版心内做最大等比缩放和整体平移；A4 页面剩余空白可以存在，但不得改变主图体宽高比。 |
| 把“适量留白”误解为页面空白，或用页面空白掩盖框内松散 | 页面剩余空白不计入框图留白审计。只审计框内字形安全距离、模块间距和容器内部占用率；不得通过缩小整张图制造所谓留白。 |
| 公式使用普通文本、图片或伪公式 | 凡用户要求公式可编辑或任务确认 Office 模式，全部公式必须是 PowerPoint Office 原生专业公式；逐个读取非空 MathZone 并在最终渲染核对。普通文本、图片和空占位框均为阻断项。 |
| 连续时间轨迹的相邻状态观测/因子连接被画成直线、折线或 V 形拼接 | 按论文与参考页保持“相邻状态节点—单弧—因子”的曲线语法。一条逻辑观测对应一个原生可编辑曲线对象，弧向、端点和因子区间中心必须正确。 |
| 本应水平或垂直的直箭头发生斜线 | 先让相连框体中心轴误差 `≤ 0.1 pt`，再创建原生直连接器并连接真实锚点；不得拖端点伪造、不得用折线迁就错位框体。 |
| 箭头使用空心头，或头部过大、箭身过细，短连接段呈现头大尾小 | 用户或参考图要求实心时，显式使用实心三角头。`0.9–1.3 pt` 普通细线默认使用窄型、短型头部；只有线宽、通道和参考图同时支持时才升级为中等头部。箭身可见长度必须明显长于头部，短通道先增加框间距，不得单独放大头部。 |
| 只检查箭头存在和两端已连接，未检查视觉方向、头身比例和锚点身份 | 同时读取 `BeginConnectedShape`、`EndConnectedShape`、首尾头型、头宽、头长、线宽、虚实和端点坐标，并在最终渲染逐条检查目标端、方向、直线共轴和头身协调。 |
| 文本出现孤字、孤 token、溢出、硬回车碎行或紧贴边框 | 按最终可见字形检查。字形到框体上、下、左、右边界均至少保留当前字号 `0.5×` 的安全距离；普通紧凑框通常不超过 `1.0×`，避免空壳。任何孤字、孤 token、孤立标点、项目符号独占行和溢出均为阻断项。 |
| 只按文本框外框或 `BoundHeight` 判断合格 | 同时检查实际行数、`BoundWidth`、可用宽高、四边内边距和 100%–200% 最终渲染；文本框不越界不等于字形安全。 |
| 修改、审计或异常清理影响非目标页、其他 PPT 或用户 PowerPoint 会话 | 只控制明确授权的 PPTX 和页码；冻结未授权页。默认保持目标 PPT 打开，禁止关闭其他演示文稿、调用 `Application.Quit()`、杀进程或全局清理。 |

本节的最小交付证据为：最终保存状态的目标页原生渲染、公式对象类型回读、连接器端点身份与几何回读、逐框文字行数/溢出/四边安全距离结果，以及主图体宽高比与写入前冻结值的对照。任一项缺失时不得声称本页通过审核。

## 内置五页模板风格自动路由（当前规则）

本节适用于“根据已有本文、论文段落、章节或提纲生成 PPT 可编辑框图”且用户没有指定另一份模板的任务。权威模板资产为 `../assets/paper-figure-style-template.pptx`：第 1–2 页定义 `叙述背景型`，第 3–5 页定义 `方法逻辑型`。用户明确指定风格或另一份模板时，以用户最新要求为准。

### 语义判别与分页

1. 先把正文拆为“主张/对象—关系—结果”账本，再按关系语义判断，不得只按章节标题或关键词机械分类。
2. 以下内容选 `叙述背景型`：研究背景、现状与痛点、技术演进、来源扩展、多源输入、总体作用、研究价值、优势或影响；关系主要是演进、汇聚、分类、支撑、影响和结果，且不要求表达内部算法状态、残差、约束或反馈回路。
3. 以下内容选 `方法逻辑型`：算法步骤、模块依赖、输入—处理—输出、状态变量、残差、约束、数据关联、滑动窗口、优化、反馈、局部—全局后端、通信、协同或因子图；关系必须显示方向、端点身份和拓扑。
4. 同一段同时包含背景叙述和方法机制时拆成两页或两张图，顺序固定为“叙述背景型在前、方法逻辑型在后”；禁止把前两页的宽松叙事卡片和后三页的密集方法语法混入同一页。
5. 用户未指定风格时自主选择，不额外询问 `极简线条`/`彩色框`。只有语义证据不足以区分、或两种路由会导致明显不同的交付范围时才请求确认。

### 源页映射

| 内容结构 | 映射源页 | 必须保持的构图 |
|---|---:|---|
| 背景、局限与研究目标递进 | 1 | 三个水平等宽阶段框，每框下方独立短说明，阶段间使用真实绑定的直线连接器 |
| 多源信息支撑研究范围与目标 | 2 | 左侧三路来源，中间研究范围，右侧研究目标；来源以直线或单对象折线汇聚 |
| 单条输入—处理—输出管线 | 3 | 五个水平流程节点，输出向下连接评估节点 |
| 多分支处理与汇聚 | 4 | 左输入、中间三个等宽分支、右侧融合和输出，分支关系用真实端点表达 |
| 局部处理与全局融合 | 5 | 左右两个范围容器，各含上下流程节点；局部更新通过折线进入全局融合 |

每个输出页必须在 `template-frame-map.json` 中记录 `sourceSlide`、`narrativeRole`、`reuseMode: duplicate-slide` 和精确 `editTargets`。不得把“看起来相似”作为源页映射依据；映射以关系拓扑和版面轮廓同时匹配为准。

### 严格模板复用契约

1. 制作前检查模板全部五页的原生对象、渲染、字体、填充、线色、线宽、坐标、母版和布局。复制映射源页或其完整原生对象组后编辑继承对象；不得只从截图、配色或“风格感觉”重新画一页。
2. 保持 `16:9`、白底和源页刻意留白。发布模板为从零构建的通用示例，不含真实论文内容；示例标签和拓扑只用于选择合适版式，实际内容以当前用户的正文和已确认骨架为准。新增内容通过复制同级对象、延续现有行列网格或拆页解决。
3. 保持源页的字体族、字号、字重、行距、文本内边距、对齐、垂直锚点、框体几何、圆角状态、填充、线宽、箭头头型和路径语义。文字不适配时先压缩措辞、选择更合适的源页或拆页，禁止静默缩小字号。
4. 继承对象默认 `keep`；只有映射中明确列出的对象才能 `rewrite`、`replace` 或 `delete`。优先在原形状自身的 `TextFrame/TextFrame2` 中改字，禁止在旧对象上覆盖新文本框或用图片遮盖。
5. 新增同级节点只能复制本页最近的同类原生对象并复用其尺寸、线宽、填充、文本样式和间距；不得引入模板中不存在的卡片、渐变、阴影、图标体系或 UI 式组件。
6. 框体、节点、文字、直线、折线、曲线、箭头和公式保持 PowerPoint 原生可编辑；复杂实验图或真实地图只能作为独立图片层。禁止整页截图、整组框图 SVG 或栅格化方法流程。

### `叙述背景型`视觉规范（模板第 1–2 页）

- 共性：白底、圆角矩形、深海军蓝文字 `#142B43`、青绿线色 `#147D7A`、浅青填充 `#EDF7F4`，无阴影、无渐变、无装饰性图片。示例中英文使用 Microsoft YaHei，实际任务服从用户已确认字体与学校模板。节点采用两行短标签，中英文均 18 pt，中文加粗、英文常规；其余字号以原生模板对象为准，不沿用旧版本模板的坐标或字号。
- 第 1 页递进式：三阶段水平排列，各有下方短说明，节点等宽并共用中心轴。按“背景—局限—目标”的通用演示关系理解版式，不把这些标签作为必须出现的论文事实。
- 第 2 页汇聚式：左侧三路来源汇聚到中央研究范围，再进入右侧目标；同级来源统一尺寸、填充和线色。目标可用柔金边线 `#B18D3F` 和浅金填充 `#FBF7EB` 区别，只有语义角色不同才使用强调色。

### `方法逻辑型`视觉规范（模板第 3–5 页）

- 共性：沿用前两页的字体、青绿与海军蓝体系，左上明确说明方法图主题。模板内容为“输入、预处理、模块A/B/C、融合、输出、评估”等通用标签，无公式、研究数据或真实论文方法。
- 矩形表示处理节点，浅色范围容器表示局部或全局分区；节点之间使用真实绑定的原生直线或单对象折线连接器。模板没有定义状态、残差或数学约束，实际需要时必须从当前正文获取依据后再构建。
- 第 3 页为“水平处理管线 + 下方评估”，第 4 页为“输入分支 + 三路处理 + 汇聚输出”，第 5 页为“左局部 + 右全局”。模板中的单向连接不能被当作当前论文的算法依据，实际反馈或额外约束必须在正文和骨架中得到确认。
- 连接器线宽、箭头方向、端点身份和图层继承模板并通过最终渲染确认；不得出现正文式长段落、文字碰撞或靠缩字塞入。同级分支与同一父模块内部保持统一颜色。

模板可由 `scripts/figure/build_generic_style_template.py` 重新生成。使用脚本的 `--output` 将预览写入独立工作路径，禁止为了生成示例覆盖用户已有演示文稿。

### 风格一致性审计

1. 将最终页与映射源页并排渲染，逐项核对页面轮廓、内容占用区、主视觉中心、行列基线、同级框体尺寸、字体层级、颜色、线宽、箭头头型、虚实线和留白；未记录的偏离均视为错误。
2. 对未要求改变的结构，归一化坐标、尺寸、间距和联合边界相对源页的偏差不得超过 `2%`；因内容变化需要偏离时，写入 `deviation-log.txt`，说明原因并保持同一视觉语法。
3. 检查最终 PPTX 中全部对象可编辑、所有逻辑连接器命中预期端点、无空占位符、无覆盖式重复文本框、无文字溢出、无单字行、无碰撞，并执行本文件既有连接器、原生对象、视觉覆盖和 OOXML 审计。

## Paper-Fig-Skill

### 目标

以最快速度交付一个质量良好、可继续编辑的 PPTX。已验证实现的普通单页以 3–5 分钟为目标；复杂抠图或公式任务按“原生对象优先与快速生成”分配时间，不把 10 分钟预算视为必须用满。

### 最高优先级安全边界：只控制本次目标 PPT

本节高于速度目标、构建流程、审查流程、PowerPoint 进程清理和任何工具默认行为。违反任意一条即立即停止自动化，不得用“需要清理实例”“由自动化启动”“共用同一 PowerPoint 进程”作为例外。

1. 自动化只拥有用户本次明确指定的唯一目标 PPTX 的控制权。开始前必须把目标文件的规范化绝对路径写入只读变量 `AUTHORIZED_TARGET_PPTX`；未取得明确目标路径时，禁止启动或连接 PowerPoint。
2. 只允许对 `Presentation.FullName` 与 `AUTHORIZED_TARGET_PPTX` 逐字规范化匹配的演示文稿执行读取对象、激活、修改、保存、导出或关闭。禁止按标题模糊匹配、窗口顺序、`ActivePresentation`、最近文件或“当前可见窗口”推断目标。
3. 除仅为建立隔离清单而读取 `FullName`、`ReadOnly`、`Saved` 和进程标识外，严禁读取、激活、切换、修改、保存、另存、导出或关闭任何非目标演示文稿。尤其禁止把用户未保存的其他演示文稿置为 `Saved=true`、使用 `Close` 丢弃更改或触发任何保存提示。
4. 启动前记录所有既有 PowerPoint 进程和已打开演示文稿的绝对路径；任务期间把它们视为不可触碰保护对象。若目标与其他演示文稿共享同一 PowerPoint 应用实例，只操作目标 `Presentation` 对象，完成后仅在确认目标由本任务打开且无需保留时关闭目标；不得关闭共享实例。
5. 严禁调用 `Application.Quit()`、`taskkill`、`Stop-Process`、按进程名结束 `POWERPNT.EXE`、关闭所有窗口、遍历 `Presentations` 批量关闭或任何等价的全局退出/清理操作。即使本任务曾创建 PowerPoint COM 对象，只要实例中存在非目标演示文稿，也绝不允许退出该实例。
6. 默认不关闭目标演示文稿。只有用户明确要求关闭，或本任务在独立隔离实例中打开了目标且关闭已被写入本次执行计划时，才允许调用该目标 `Presentation.Close()`；关闭前再次核对完整路径并确认它是唯一受影响对象。释放 COM 引用不等于退出应用，不得为释放引用调用 `Quit()`。
7. 所有异常、超时、验证失败和脚本清理分支都必须遵守同一隔离规则。异常处理只能释放本任务持有的对象引用和临时文件；禁止把“确保无残留进程”实现为关闭用户实例。无法证明对象身份或实例隔离时，保持 PowerPoint 原状并停止。
8. 每个使用 PowerPoint COM 的生产脚本必须在运行前通过静态检查：不得包含全局 `Quit`/杀进程/批量 `Close` 路径；必须包含目标绝对路径核对。审查或辅助脚本同样适用，不得因“只读”而放宽。

最高优先级硬门槛：

1. 任何文字或公式的实际可见内容不得与框线、箭头、连接线、形状、图标、图片、其他公式或其他文字发生碰撞。公式与文字执行完全相同的零碰撞标准；Office 原生公式按最终可见字形判断，MathType 按非空 `Equation.DSMT4` OLE 的实际可见边界判断，不能只检查目标占位框。文字或公式位于所属容器内部不算碰撞，但可见内容必须与容器边界保留安全内边距。该规则是质量审核中的最高原则，存在任意一处即优先修复；仅在已完成第二次审查时，允许如实记录后按审查上限交付。
2. 每条折线或折线箭头必须是一个 PowerPoint 原生可编辑对象；禁止用多条直线、多个箭头或多个形状拼接后组合冒充一条折线。
3. 除源图明确竖排、单字标签或逐字排列外，任何横排文本都不得出现单个汉字、单个英文 token、孤立标点或项目符号独占一行。

以上门槛高于局部尺寸复刻、同级等宽、对齐、留白、间距、装饰细节和 10 分钟时间目标。

质量优先级：

1. 消除文字和公式与任何框线、箭头、形状、其他文字、其他公式或其他元素的碰撞；
2. 保证每条折线和折线箭头是单个 PowerPoint 原生对象，绝不拼接；
3. 消除横排文本的单字行、孤立 token、孤立标点和项目符号行；
4. 其他文字排版；
5. 内容、区域底色与配色覆盖完整；
6. 箭头类型、方向、目标和路线；
7. 留白、对齐和页面平衡；
8. 次要装饰细节。

参考图复刻必须一一对应：不得删减、合并、改写或新增源图中的模块、文字、形状、曲线和箭头。禁止近似重构和简化图形；提速只能来自一次构建、组件复用和减少重复检查，不能来自降低复刻忠实度。

普通任务由主智能体直接完成，不启动子智能体，不生成多个竞争版本。

### PowerPoint 文件与页面动作闸门

已有 PPT 的“保存到哪里”和“页面如何变化”属于不同参数，必须分别冻结。任何通用工具的“保留源文件并导出副本”默认行为都不得覆盖用户确认的页面动作。

1. 写入前固定记录：`AUTHORIZED_TARGET_PPTX`、`file_action`、`slide_action`、`insert_position`、`preserve_source_slide`。
2. `file_action` 只允许：
   - `edit_same_pptx`：保存回唯一目标 PPTX；
   - `save_as_new_pptx`：仅当用户明确要求另存整个 PPT 时使用。
3. `slide_action` 只允许：
   - `edit_existing_slide`：直接修改指定页；
   - `insert_blank_slide`：在原 PPT 内新增空白页；
   - `duplicate_slide_in_deck`：在原 PPT 内复制指定页后修改；
   - `none`：只读检查。
4. 用户说“在原 PPT 新建/添加一页”时固定为 `edit_same_pptx + insert_blank_slide`；用户说“保留原页再改/复制第 N 页做一版”时固定为 `edit_same_pptx + duplicate_slide_in_deck`，默认紧跟源页插入。
5. 用户只说“修改第 N 页”时固定为 `edit_same_pptx + edit_existing_slide`；不得擅自复制页面或创建新文件。
6. 只有明确出现“另存、生成副本、不要改原 PPT”等语义时，才允许 `save_as_new_pptx`。
7. 临时只读副本和 QA 导出只能位于构建目录，不是交付物，不得用它们替代原 PPT 内新增页或复制页。
8. 写入前输出一句无歧义的动作摘要；如果用户已经明确，不重复提问。例如：`章节图.pptx｜复制第 1 页为新第 2 页｜保留原页｜不另存整个 PPT`。
9. 若目标已打开，精确绑定唯一目标 `Presentation` 并在其中完成页面动作；不得因文件锁转为另存副本。无法安全绑定时停止，不得产生竞争版本。

首次生成完整可编辑 PPTX 后，默认只进行 `1` 次合并审查。若发现真实问题，先汇总全部问题，在同一写入会话集中修正 `1` 次，再进行第 `2` 次定向审查。第 `2` 次审查后必须停止修改并交付当前版本；该停止条件优先于本 skill 中所有要求“继续修复”或“存在问题不得交付”的语句，但不得把残留问题虚报为已解决。只有用户明确授权继续返工时，才允许突破该默认上限。

### PPT 构建排版统一原则（全部任务默认）

### Windows 下的 PPT 运行时初始化

正式生成 PPT 或调用 `@oai/artifact-tool` 前，必须先完成一次运行时预检：

1. 先调用工作区依赖发现工具，使用其返回的 Node.js、Node.js packages 和捆绑运行时绝对路径；不得从当前目录、技能目录或历史版本号猜测运行时位置。
2. 明确区分工作区根目录与捆绑运行时根目录。`C:\Users\<用户>\Documents\...` 可以是正确的工作区根目录，但捆绑运行时通常位于 `C:\Users\<用户>\.cache\codex-runtimes\codex-primary-runtime`；不得因为两者不同而声称工作区根目录错误。
3. Windows 中若 `HOME` 为空，在执行 `setup_artifact_tool_workspace.mjs` 的同一进程内临时令 `HOME=USERPROFILE`；若 `USERPROFILE` 也不可用，则使用系统用户目录。不得让初始化器以 `process.cwd()` 代替用户目录。
4. 若错误路径包含 `<工作区>\.cache\codex-runtimes\...`，立即判定为运行时根目录推导错误，不重复执行同一失败命令。先验证依赖发现工具返回路径下的 `node_modules\@oai\artifact-tool\package.json` 和构建入口确实存在，再继续。
5. 官方初始化器仍失败但本地捆绑包已验证可用时，只允许一次回退：将临时制作目录的 `node_modules\@oai\artifact-tool` 链接到已验证的本地包。链接目标必须来自本次依赖发现结果，不得硬编码插件版本或把链接建到最终交付目录。
6. 该异常属于 PPT 运行时初始化层，不属于本技能的内容分析、版式或用户工作区配置错误。对用户说明时应准确称为“Windows 下 `HOME` 缺失导致初始化器误从当前目录推导运行时路径”；恢复成功后继续主任务，不要求用户更换工作区。

### 基础 PPTX 结构完整性闸门

基础 PPTX 的结构验证必须发生在 Office 或 MathType 公式写入之前。公式流水线只能处理已经证明可被 PowerPoint 正常打开的文件，禁止把公式写入成功当作 PPTX 包结构正确的证明。

1. 所有线条、直箭头、折线段、自由路径和反向绘制辅助函数都必须先规范化几何：`left=min(x1,x2)`、`top=min(y1,y2)`、`width=abs(x2-x1)`、`height=abs(y2-y1)`；方向使用 `flipH`、`flipV` 或端点顺序表达。禁止向 PPTX 写入负 `width`、负 `height`、负 `cx` 或负 `cy`，包括向左、向上、旋转后和反馈路径中的线条。
2. 页面坐标换算只允许引用生成脚本中的同一组权威画布常量，如 `sourceWidth`、`sourceHeight`、`slideWidth`、`slideHeight`；后处理、连接器修复和审计脚本不得重新手写另一组近似比例。执行后处理前用至少两个已知对象反算坐标并断言误差，禁止把 `2000`、截图宽度或显示缩放尺寸误当成真实源图宽度。
3. 首次保存含全部非公式对象和唯一公式目标框的基础 PPTX 后，立即运行 `../scripts/figure/validate_pptx_ooxml_geometry.py --input <pptx>`。只有 ZIP CRC、XML 解析、内部关系、形状 ID 和全部 DrawingML extent 检查均通过时，才允许继续。
4. 结构脚本通过后，以“只读基础包审计会话”按权威绝对路径启动 PowerPoint，确认 `FullName` 精确匹配，并完成一次原生打开和页面导出。只以 `Presentation.ReadOnly` 实际值判断只读状态，不以 `/r` 参数、文件属性或启动命令推断；必须在此时验证没有“PowerPoint 发现内容有问题”“需要修复”或等价提示，未通过时禁止启动 Office/MathType 公式流水线。
5. 出现修复提示时，禁止点击“修复”后覆盖权威 PPTX，也禁止把修复后的文件继续作为公式输入。保留错误现场，回到生成脚本修正非法几何或包关系，再重建同一权威路径；该重建发生在首个完整可编辑 PPTX 形成之前时不计修正轮次。
6. 基础包通过后记录文件 SHA-256、最后写入时间和公式流水线启动阶段；公式完成后再次记录。后续出现异常时，先依据两次文件状态、流水线 stage 和 PowerPoint 原生打开结果定位是“基础包生成”“公式写入”还是“后处理”阶段，禁止没有证据就归因于 MathType、PowerPoint 安全策略或用户文件。

### 公式写入前的原生视觉与幂等闸门

结构检查通过不等于视觉正确。参考图任务在启动 Office/MathType 前必须从基础 PPTX 完成一次 PowerPoint 原生渲染并实际查看原始尺寸全页及高密度区域；未完成以下检查不得写入公式：

1. 将源图的箭头头型、虚实线型、颜色和头部数量加入基础包审计。禁止未经验证直接使用 Office 数值枚举；PowerPoint COM 中 `msoArrowheadNone=1`、实心 `msoArrowheadTriangle=2`、空心 `msoArrowheadOpen=3`，源图为实心时必须读取最终 `EndArrowheadStyle=2`，不能只看“存在箭头头部”。
2. 不信任生成后端对 `dot`、`dash`、箭头头型或线端样式的名称映射。虚线和点线必须在 PowerPoint 原生渲染中逐框核对；需要圆点线时明确设置并读取 `msoLineRoundDot=3`，发现被渲染为实线时在基础包阶段修正。
3. 标题、正文和公式使用互不重叠的矩形槽。有框模块的标题和正文必须写入所属 PowerPoint 原生形状自身的 `TextFrame/TextFrame2`；只有无所属外框的标题、注释和公式说明才使用独立文本框。含“标题 + 公式”的模块必须先划分标题带和公式区，禁止让任何文字对象覆盖整个模块后再把公式目标框叠在其上。
4. 正式公式写入前，用预计公式可见矩形而非空目标框线条执行一次 `formula_target_connector_collision_count` 和 `formula_target_text_collision_count`；两者必须为 `0`。公式插入后只用于核对实际 OLE 尺寸偏差，不得把首次布局碰撞推迟到 MathType 完成后。
5. 自由多段线和折线的碰撞必须逐段计算，曲线按真实节点或采样轮廓计算；禁止用覆盖大片空白的整体外接矩形代替路径后制造误报，也禁止因此移动本来正确的公式。
6. 所有后处理脚本必须幂等。为脚本拥有的对象使用稳定前缀或完整对象注册表；再次运行前删除全部同前缀旧对象和代理锚点，再创建一次，并断言逻辑路径名唯一、预期路径数等于实际路径数。禁止依赖容易遗漏的新旧名称硬编码清单。
7. 基础包视觉检查必须在公式流水线之前同时核对：箭头头型、点/虚线样式、标题与公式分区、公式目标安全槽、逻辑路径唯一性和预期对象数量。任一项未核对时禁止以“结构检查已通过”为由继续。
8. 公式或文字位置修正必须由实际外接框、路径段和 `3–4 pt` 安全距离计算最小位移，一次移动到满足条件的位置；禁止凭感觉连续移动若干像素并消耗修正轮次。保存前先在内存或只读几何模型中验证修改后的碰撞计数预计为 `0`。
9. 第 1 次合并审查发现问题时，一次性汇总全部剩余阻断项，并仅在几何计算证明集中修正方案能够消除它们后保存；不得用唯一一次修正机会进行未经验证的试移。若无法证明为零，在保存前先重做空间分配和内存几何验证，避免第二次审查仍暴露可预防问题。
10. 合并 PowerPoint 会话：默认只允许一次基础包写入会话、一次基础包只读审计、一次公式批处理会话和一次最终只读审计；同一阶段的连接器、线型、图层和文字位置修改必须在同一写入会话完成。只有审计发现真实问题时才追加修正会话，不得为每个小步骤反复打开和关闭 PowerPoint。
11. 每次计划打开 PowerPoint 前向用户说明本次会话目的；若实际需要额外重开，先说明触发原因。禁止在仍可能发生修正时承诺“只会再打开一次”，也不得把自动化重复启动造成的可见窗口干扰留给用户自行判断。

### PowerPoint 启动的强制前置闸门

以下规则属于界面操作的强制前置条件；任意一项未通过时，禁止继续制作：

1. **始终按路径直接启动目标 PPTX。** 只要目标文件路径已知，启动或打开 PowerPoint 的第一步必须把该 PPTX 的绝对路径直接传给 PowerPoint 或系统文件关联；路径含空格或中文时使用完整字面路径并正确引用。禁止先打开空白 PowerPoint、进入“文件 > 打开”或系统文件选择器，再通过截图、坐标点击、键盘输入、剪贴板或逐级浏览目录来定位目标文件。禁止为了打开文件而反复截图或枚举窗口。
2. 目标 PPTX 已在 PowerPoint 中打开时，直接激活并复用标题匹配的现有窗口；不得重复启动或再次打开同一路径。直接启动后只允许读取标题栏或当前窗口状态确认文件是否正确；截图仅用于确有必要的视觉验证，不能作为打开文件、寻找路径或判断下一步导航的默认手段。目标路径不存在时立即停止并报告，不得打开空白演示文稿代替。
3. 打开前先声明本次会话是“写入会话”还是“只读审计会话”。任何可能移动、缩放、删除、重连、改图层或保存对象的步骤都必须以可写模式打开；打开后先读取 `ReadOnly`/保存能力并确认可写，再执行第一处修改。禁止先在只读演示文稿中完成一批修改，直到 `Presentation.Save` 报错才发现无法保存。
4. 每次打开后立即把 `ActivePresentation.FullName` 与权威 PPTX 的规范化绝对路径逐字比较；不一致时不得继续。写入会话只保存该权威路径，禁止因只读错误临时另存副本、改名或产生第二个竞争版本。
5. 优先使用 `../scripts/figure/powerpoint_window_binding.ps1` 复用或按权威路径启动并绑定 PowerPoint 会话。若 `New-Object -ComObject PowerPoint.Application` 返回空对象，或访问 `Visible`、`Presentations`、`Quit` 时出现 `TYPE_E_CANTLOADLIBRARY`，立即丢弃该无效实例，不继续访问其属性；只启动一次目标 PPTX，在有界等待内使用 `GetActiveObject('PowerPoint.Application')` 取得精确路径会话。清理阶段的 `Close`、`Quit` 或 `ReleaseComObject` 异常必须单独捕获，不得覆盖和掩盖主操作的原始异常。
6. 只允许关闭经完整路径核验且由本任务明确启动的目标演示文稿；默认保持目标打开。绝不关闭、保存或切换其他演示文稿，绝不调用 `Application.Quit()` 或强行终止任何 PowerPoint 进程。任务结束时仅记录进程和文件锁状态，不以“清理残留”为由改变任何进程或窗口状态。

#### 参考图忠实复刻

参考图本身就是结构模板、配色和内容依据，不得重复询问“使用什么模板”“使用什么配色”“根据什么内容”。只确认：

1. 页面尺寸、方向、是否保持原图比例；
2. 字体和字号范围；
3. 需要新增、改写、替换或转换公式时，按上述内置公式流程三项必问确认公式类型、目标 PPTX 完整路径和分页形式；仅保留已有公式时标明“原公式对象与符号保持不变”。

##### Hybrid Reconstruction（混合重建）

- 用户明确提出 `Hybrid Reconstruction`、`Hybird Reconstruction`，或同时要求“有框文字与框体一体、无框文字可独立编辑、箭头为 PPT shape、单图标为 SVG、复杂图片为独立图片层、禁止整图插入”时，必须完整读取 [Hybrid Reconstruction 模式](figure-workflow.md) 并在参数清单中标明该模式。
- 该模式先建立逐对象分类清单，再按对象类型分别重建；不得把“复杂图片保留”扩大解释为允许嵌入整张参考图，也不得把图标 SVG 扩大解释为允许把框图、箭头、文字或多个图标合成 SVG。
- 该模式的四级语义图层是最终 Z 序，不是创建顺序。必须先创建可见节点形状，再把连接器直接绑定到这些可见形状的真实连接点，最后调整相对 Z 序；禁止为了“先画箭头”或满足图层顺序而普遍创建 `ANCHOR_*`、`PROXY_*` 等透明代理形状。
- 复杂照片、实物、设备、实验图、热力图和不可可靠拆分的复杂图表必须提取为独立图片层，并按主体可见轮廓或源图中明确的图片边界进行物理抠图。抠图结果必须去除参考图中叠加或邻接的文字、箭头、连接线、框线、面板底色、水印、页码和相邻对象；禁止直接截取包含这些干扰元素的矩形区域，禁止用 PowerPoint 裁剪框隐藏仍嵌在图片数据中的整张参考图。
- 抠图后透明区域必须是真透明，边缘不得残留白边、灰框、截断文字、箭头碎片或其他对象像素。原图中属于复杂图片自身且无法可靠分离的内部刻度、图例和标注可保留，但必须在对象清单中逐项声明；能独立重建的外部文字、箭头和框体必须重建为独立 PPT 对象。
- Hybrid Reconstruction 成品在交付前必须运行 `../scripts/figure/audit_connector_target_identity.py` 和 `../scripts/figure/audit_hybrid_visual_coverage.py`；前者核对连接目标身份，后者核对命名对象、区域填充与源图取样颜色。任一脚本未通过时，不得用视觉贴边或整页缩略图替代专项结论。

#### 基于已有 PPT 的优化修改

当输入为已有 `.ppt` 或 `.pptx`，且用户要求翻译、统一文字、增加模块、调整排版或优化图形时，将源 PowerPoint 视为结构、对象和视觉风格的权威来源。除非用户明确要求重画或重构，否则执行以下硬规则；这些规则优先于从零绘制和通用版式优化：

##### 论文驱动系统框图防错闸门

- 本节只补充论文内容、系统逻辑和关系图拓扑规则；所有字体、框体、留白、箭头、曲线、图例、图层与碰撞标准统一服从 [PPT 构建排版统一原则](figure-workflow.md)。
- 只要任务同时涉及已有 PPT 与论文、Word、章节内容或系统逻辑，正式分析和修改前必须完整读取 [已有 PPT 论文系统框图防错规则](figure-workflow.md)，并把其中“交付前强制清单”加入当前工作检查表。
- 先建立论文章节证据账本和逐条连接拓扑账本，再检查参考页原生对象类型；三者未冻结时禁止打开写入会话。
- 论文中明确不存在的先验、残差、模块或连接属于禁止项，不能用领域常识补写。系统框图只使用短标签，不放正文式长说明。
- 不确定的曲线、Arc 缩放、锚点或图层必须先完成一次不保存的内存渲染测试；未经验证不得消耗权威 PPTX 的修正保存轮次。

##### 原生对象复用与修改边界

- 复杂框图、树、点云、轨迹、图例、曲线、特殊轮廓、连接器、公式和装饰已有可编辑对象时，直接复制、移动、组合或编辑原对象。禁止近似重画、用简化图标替换、截图回填、重新生成相似图形，或为了排版方便删去原模块。
- 只修改用户授权的对象和内容。未要求修改的页面、模块、文字、公式、图形、颜色、线型、层级和连接关系保持不变；不得创建 Word、PDF、报告或其他无关产物。
- 翻译或统一文字时，有框模块优先直接替换其原生形状 `TextFrame/TextFrame2` 内的文字，使文字与框体保持单一对象；无所属外框的标题、注释和图例文字才在原独立文本框内替换。源 PPT 若以“框体 + 覆盖文本框”表达普通有框模块，应在不改变几何、字体、颜色和对齐的前提下把文字写回框体并移除重复文本框。文字嵌在图片、EMF、组合图形或其他不可独立编辑对象中时，先说明限制并确认是否允许覆盖或局部重画；未经许可不得用新文本遮盖原标注。
- 已有公式默认保留原对象、对象类型、符号、位置和尺寸。只有用户明确要求新增、改写、替换或转换公式时才启动本 skill 的公式流水线；不得因页面中存在公式就重新制作。
- 原连接器、自由曲线、折线和箭头可随所属模块整体移动，但不得无故删除、拆分、改线型、改头部、改变锚点身份或重新路由。

##### 复杂模块比例保护

- 将含多个子对象的复杂图形视为不可变内部几何的整体。优先按原尺寸复制并平移；确需缩放时，先整体成组并锁定纵横比，只做等比缩放。
- 禁止横向或纵向非等比拉伸复杂模块，禁止分别缩放其子对象，禁止拆组后用独立坐标重排内部元素，也禁止通过压扁、拉宽或缩小局部对象来“凑”目标宽高比。
- 整体移动或等比缩放后，保持模块内部相对坐标、宽高关系、旋转角、节点间距、Z 序、遮罩、锚点、连接关系、曲线弧向、图例对应和公式位置不变。
- 需要为新增内容腾出空间时，优先重新分配外围分区、移动完整模块、调整模块间距或利用页面留白；不得侵占复杂模块内部空间。原图已失真、拆组或错位的中间稿不得继续作为修改基础，必须回到用户源 PPT 的干净副本重新开始。
- 对每个大框、虚线容器和分区执行内容占用率检查。若出现宽度或高度超过相邻模块尺寸 `0.5×` 的连续大片空白，必须自动重新分配完整模块的尺寸、位置和间距，使内容沿主方向均匀铺满；不得保留“模块挤在一端、另一端空洞”的布局，不得通过增加正文式说明、无意义装饰或非等比拉伸受保护复杂模块来填空。
- 图体宽高比属于当前用户控制的任务参数。符合顶部“三栏递进式学术系统图”适用条件且用户未另行指定时，主图体预填约 `3:2`；否则不设比例默认值。参数闸门仍须记录比例数值或范围、允许误差、作用对象（页面、主图体、指定区域或指定模块）以及是否保持源模块比例；不得把主图体比例扩展为页面或复杂源模块比例，也不得改变页面尺寸或对受保护源模块做非等比缩放。

##### 约束冲突闸门

- 正式修改前同时核对页面尺寸与方向、目标图体比例、字体范围、必须保留的原模块、原模块比例不变、文字完整性和新增内容所需空间。
- 若用户确认的页面尺寸与方向、目标图体比例、字号下限、全部元素保留和复杂模块不缩放等要求在当前画布上不能同时满足，立即停止正式修改并请用户确认优先级。禁止自行用非等比拉伸、删减模块、越界缩字、重做公式或覆盖原标注来消解冲突。
- 字体统一按对象层级执行，不做破坏布局的全页强制替换。标题、正文和密集继承标签可分别使用已确认区间内的字号；允许密集原生标签采用区间下限，但不得低于用户确认值，也不得因此改变原模块比例。

##### 骨架、版本与原生验收

- 既有 PPT 仅做文字替换、等比移动或局部增补且不改变拓扑时，不新增从零制作骨架闸门。需要重组区域、改变模块关系或新增主流程时，按“根据文字从零制作”提交骨架；骨架中应使用源 PPT 复杂模块的实际缩略预览表达占位和视觉重量，并标注“仅供审核”，不得用简化替代图误导最终效果。正式 PPT 仍必须使用源文件的原生可编辑对象。
- 每次正式修改从用户指定源 PPT 的干净副本开始，记录精确源路径、输出路径、页面索引和允许修改范围。不得覆盖源文件，不得在已拉伸、拆组或绑定失败的中间文件上连续修补。
- 保存前后建立比例保护账本：记录每个受保护复杂模块的边界框、宽高比、对象数、连接器数及公式对象数/类型。整体等比缩放时，横向与纵向缩放因子必须在浮点容差内相等，模块宽高比变化率必须 `≤ 0.1%`；超过即作废该轮并从干净副本重做。
- 最终必须由 PowerPoint 原生打开、保存、重新打开并渲染后验收。通用 OOXML 验证器只作补充；若错误继承自源文件但 PowerPoint 可正常打开渲染，记录为源文件遗留问题，不得盲目“修复”关系、对象 ID 或公式内部结构。任何必要修复完成后都必须再次原生打开和渲染。
- 原生验收除碰撞和越界外，还要逐项对照源文件检查：受保护模块宽高比、对象数量、连接器数量与路线、公式数量与类型、主要层级、全部原图元素以及新增内容。任一复杂模块被拉伸、漏项、简化、栅格化或失去可编辑性，均为交付阻断项。

#### 根据文字、提纲或结构说明从零制作

`standard` 或 `submission` 从文字新建整页、重构主拓扑时，在生成正式内容或开始绘图前确认：

1. **模板或结构风格**：使用哪张参考图、PPT 模板或哪类结构，例如纵向技术路线、横向流程、分层框架、矩阵、环形机制或章节安排图；
2. **框图视觉风格**：按本文件顶部唯一风格路由选择并记录；只有路由无法确定且两种方案会实质改变结果时才让用户选择 `极简线条` 或 `彩色框`；
3. **配色**：沿用参考模板、使用单位/课题组配色，或由用户指定主色、强调色和背景色；
4. **内容依据**：根据哪份文档、论文、提纲、表格或用户提供的文字制作；同时确认是忠实提取、压缩总结还是允许重组归纳，以及需要包含哪些板块；
5. 页面尺寸和方向；
6. 字体和字号范围；
7. 图中存在公式时，按上述内置公式流程三项必问确认公式类型、目标 PPTX 完整路径和分页形式。

模板、配色或内容依据任意一项未明确且无法由唯一风格路由、目标 PPT 或当前论文已确认统一规范可靠继承时，不得直接套用上一任务内容或配色。可以在同一条确认消息中给出一个推荐方案，但必须等待用户确认适用参数后再开始正式构建。

用户已经给出的要求直接冻结，不重复询问。后续 `fast_local` 修改同一张图时，只汇总本次修改范围、保持不变项、输出文件和新增参数；不要求重新确认未改变的整份参数。改变主拓扑、比例、模板或公式类型时升级到 `standard` 并确认完整适用参数。

用户明确表示“由你决定”“按推荐方案”或同等授权时，将已说明的推荐值写入整份参数清单；该授权不替代最终确认，仍须等待用户明确确认整份清单后再执行。

##### 内容逻辑骨架审核闸门

根据文字、提纲、论文、Word、表格或结构说明从零制作框图时，参数确认与正式绘图授权必须分成两道独立闸门：

1. **参数确认**只授权读取内容、分析逻辑并创建一张静态骨架预览图；
2. **骨架确认**才授权打开或修改 PowerPoint、运行正式生成脚本、正式绘制图标与细节、使用内置公式流水线插入公式、完成最终渲染审核和交付。

完成内容分析后，必须先创建一张清楚标注为“PPT 骨架预览（非最终 PPT）”的静态骨架预览图，并在对话中直接显示该图。优先生成 SVG，并可额外渲染 PNG 便于对话查看；预览图不要求可编辑。不得只用 Mermaid、等宽文本或纯文字说明替代骨架预览图。

###### 快速 SVG 框图骨架流程

骨架阶段的目标是让用户尽快审核**整体布局和模块区域**，不是提前制作正式框图。收到参数确认并完成内容逻辑分析后，按以下固定流程执行：

1. 用一句话冻结中心叙事，再列出主区域、区域内一级模块、主连接、反馈连接、重复层和公式预留位；不展开正式图标、复杂装饰、精细曲线和逐字排版。
2. 直接生成一个低保真 SVG 文件。使用简单矩形、圆角矩形、虚线容器、直线或折线路径和短标签，按参考图的大致比例表达区域位置、宽高占比、上下层级和连接方向。
3. 参考图存在“一个详细主体 + 后方复制层 + 顶部初始化 + 右侧后端”等结构时，骨架必须先复现这些大区域关系，再填写模块名；不得把参考图改造成另一种布局。
4. SVG 主体只画审核所需内容：页面/图幅边界、编号主区域、一级模块卡片、重复层轮廓、主流程、分支、反馈、跨区连接、公式占位和主要图标文字说明。图标只写语义名称，不生成正式图标。
5. 在 SVG 底部加入紧凑的区域分配说明：主区域数量与名称、宽度比例、上下比例、公式数量与位置、最终输出尺寸。不要加入大段论文摘要。
6. 保存一份当前 SVG；仅为对话显示需要时额外渲染一份 PNG。禁止打开 PowerPoint、创建可编辑骨架页、启动公式写入流程、制作中间 PPT 或把 SVG 嵌入最终 PPT。
7. 在对话中直接显示骨架并停止，等待用户明确回复“确认骨架”或提出修改。收到修改后只更新同一份完整 SVG，再次提交审核。

速度约束：普通单页骨架应在内容逻辑明确后约 1–3 分钟内生成。不要为骨架搜索网页素材、绘制正式图标、做像素级复刻或反复渲染；这些工作只在骨架确认后的正式阶段进行。

骨架预览图采用类似 PPT 页面规划稿的纵向审核版式：

1. 顶部显示“任务名称｜PPT 骨架预览（非最终 PPT）”和一句审核用途说明；
2. 中部主体按照最终页面尺寸、方向和预计图幅比例，完整画出编号主分区、模块卡片、层级、区域占比、主流程、分支、反馈及跨模块连接；
3. 底部单独设置“正式 PPT 的区域分布”说明框，至少列出主区域数量与名称、宽度分配、上下分配、已确认的公式类型与公式计划及最终输出；
4. 使用已确认的正式配色做低保真填充，使用户能够判断各区域视觉重量，但不提前制作正式图标、复杂装饰或细节元素；
5. 公式只标明公式编号、变量关系或预留位置，不创建普通文本伪公式、Office 原生公式或 MathType 对象。

骨架预览图只用于审核，不要求可编辑，也不得作为最终 PPT 的页面截图或背景。骨架确认后，以已确认预览图的模块边界和连接拓扑为依据创建唯一权威 PPTX，全部正式元素仍须是 PowerPoint 原生可编辑对象。

骨架预览必须完整说明：

- 全图要表达的中心结论、技术边界和主叙事；
- 模块名称、层级、分组及建议顺序；
- 主流程、分支、汇合、循环、反馈和跨模块连接的拓扑；
- 拟采用的分区或子图安排，如 `(a)`、`(b)`、`(c)`；
- 每个模块的主要图标元素、视觉隐喻及其与内容的对应关系；
- 计划出现的公式、变量关系、已确认的公式类型及拟放置区域；骨架阶段只说明公式计划，不提前创建普通文本公式、Office 原生公式或 MathType 对象；
- 对原文所做的保留、压缩、合并、删减或重组决定。

骨架必须让用户能直接指出“增加、删除、合并、拆分、改名、换序、改连接、改图标”中的任意修改。提交后停止正式制作，等待用户明确回复“确认骨架”“按此正式绘制”或语义等同的完整确认。用户仅提出局部修改、补充内容或表达保留意见时，先更新并重新提交**完整骨架**，再次等待确认；不得把局部意见视为正式绘图授权。

正式制作必须忠实实现最后一次确认的完整骨架。若制作中发现需要新增、删除、合并、拆分、重排模块，或改变主流程、分支、反馈、公式关系和主要图标隐喻，立即停止正式制作，更新完整骨架并重新请求确认。只调整尺寸、间距、对齐、字形换行或其他不改变语义拓扑的视觉细节时，无需重新确认骨架。

参考图忠实复刻任务不增加骨架审核闸门，因为参考图本身就是已给定骨架；但用户要求在参考图基础上重组内容、改变模块或重新设计逻辑时，按“根据文字从零制作”执行两道闸门。

### 10 分钟流程

对于根据文字从零制作的任务，约 10 分钟的正式制作计时从用户确认完整骨架后开始；等待用户审核和修改骨架的时间不计入正式制作时间。

普通单页正式制作必须完整读取并执行 [单页约 10 分钟首次通过闸门](figure-workflow.md)。参考图忠实复刻以参数确认后开始计时；如果第一次合并审查为零阻断，目标在约 10 分钟内直接交付。提速来自账本复用、一次构建、保存前预检和合并审计，不得来自简化图形或跳过检查。

| 骨架阶段 | 工作 |
|---|---|
| 参数确认后 | 读取内容，提炼中心结论、模块层级、连接拓扑、图标语义和公式计划 |
| 创建骨架 | 生成一张静态审核图：上部为完整区域骨架，下部为区域分配、公式计划和最终输出说明 |
| 提交审核 | 在对话中直接显示骨架预览图，并提供文件链接和必要的模块逻辑说明 |
| 等待用户 | 不打开或修改 PPT，不进入正式绘图或公式写入；收到修改时更新骨架预览图并再次确认 |

骨架确认后的正式制作：

| 时间 | 工作 |
|---|---|
| 0–2 分钟 | 冻结骨架或参考图，完成运行时预检和对象、文字、连接器、颜色账本 |
| 2–7 分钟 | 一次生成全部可编辑对象，并在内存中通过文字编码、图层、连接共轴、颜色完整性四个保存前闸门 |
| 7–9 分钟 | 保存唯一权威 PPTX，运行结构验证和一次 PowerPoint 原生合并审计 |
| 9–10 分钟 | 查看同一原生渲染；零阻断立即交付 |
| 发现阻断项后 | 暂停 10 分钟目标，在同一写入会话集中修正一次并执行第二次定向审查 |

默认只保留：

- 一份紧凑对象清单；
- 一个参数化生成脚本；
- 一个最终 PPTX；
- 一次合并全页审查；
- 必要时一次集中修正和一次定向复查。

不要生成中间 PPT、竞争草稿或对比材料。骨架阶段只保留一张当前骨架源图和必要的查看用渲染图；骨架确认后只创建一个权威 PPTX。不要重复重开、渲染或重建整页。

骨架预览图是正式制作前的审核状态，不是最终成品。必须在图内标注“PPT 骨架预览（非最终 PPT）”，正式 PPT 不得嵌入该预览图充当整图。

#### 合并审查与返工上限

- 从第一份包含全部请求内容和已确认公式类型的完整可编辑 PPTX 首次保存后开始计数。
- 第 `1` 次为合并审查：只打开一次最终状态，使用同一份原生渲染和同一轮对象读取，同时完成结构、颜色/填充、连接、图层、文字、公式和可编辑性检查。
- 第 `1` 次审查通过时立即交付，不再追加“保险性”渲染、复查或重复打开 PowerPoint。
- 第 `1` 次审查发现问题时，先汇总全部问题，再在一个写入会话集中修正并保存一次；禁止每发现一个问题就单独打开、修改、保存和渲染。
- 修正后只执行第 `2` 次定向审查：检查受影响区域，并复核会被该修改连带影响的全局项目。第 `2` 次审查后立即交付当前版本，默认不启动第 `3` 次审查或第 `2` 轮修正。
- 不得通过改名、另存副本、重建同页或拆分修改来重置计数。最终回复必须简要列出仍可见或已知的问题；除非检查结果确实如此，不得声称“阻断项为 0”“已全部修复”或“严格通过审核”。

#### 避免返工的首次构建规则

- 首次构建必须同时生成对象账本、Unicode 文字账本、连接器/共轴账本、颜色/填充账本和 `native-audit-manifest.json`。后处理与审计只读取这些权威账本，禁止重新手写对象名、中文文本、坐标或图层分类。
- 首次生成即固定四级语义图层：`Background < shapes < icons < text`。该顺序只定义最终 Z 序，不定义对象创建顺序。先创建带自身内部文字的最终可见节点/模块形状，再用这些可见形状建立真实连接器，之后把连接器相对调整到节点下方、背景上方，最后生成图标、无框独立文字和公式。有框模块文字属于所属 shape，不得为了置顶而拆成覆盖文本框。禁止为了让路径先出现而把连接器连接到临时透明锚点。只有 `icons` 允许使用 SVG，且每个图标必须是一个独立 SVG/独立 PowerPoint 对象；能够用 PowerPoint 内置形状、连接器或原生曲线表达的模块、节点、因子、箭头、路径和图例符号必须保留为 `shapes`，禁止把整图、整组模块、文字或多枚图标合并为 SVG。所有带填充色的区域背景、容器底板和分区底色必须发送到整个幻灯片的绝对最底层；无框独立文字和公式位于最上层。
- 创建完全部对象后、首次保存前，必须读取最终 Z 序执行全局相对关系检查：`background < path < node < icon < standalone text/formula`；节点内部文字随所属 shape 审计，不作为独立 Z 序对象。不得以创建顺序、局部置底操作或缩略图代替。`layer_violation_count` 必须为 `0`。
- 连接器 API 要求源/目标对象已存在时，必须先创建最终可见框体，再调用连接器 API。不得创建 `1–3 px` 的无填充 `ANCHOR_*` / `PROXY_*` 形状来绕过创建顺序；图层通过相对 Z 序处理，不通过替换连接目标处理。
- 首次保存前必须逐框检查文字账本精确匹配和实际边界溢出；短符号、单字符和“+”“−”等文本不得豁免。`text_mismatch_count` 与 `text_overflow_count` 必须为 `0`。
- 首次保存后、任何公式流水线之前，运行 `../scripts/figure/audit_connector_target_identity.py --input <pptx> --ledger <connector-ledger.json>` 和 `../scripts/figure/audit_hybrid_visual_coverage.py --input <pptx> --ledger <visual-ledger.json>`。连接计数必须全部为 `0`；视觉审计必须满足 `expected_object_count = checked_object_count` 且 `issue_count = 0`。
- PowerPoint 原生合并审计固定使用 `../scripts/figure/audit_powerpoint_native.ps1` 和首次构建生成的 `native-audit-manifest.json`；禁止在普通任务中临时重写原生审计脚本。该脚本必须一次取得原生渲染、对象注册覆盖、全局图层、连接端点、共轴、Unicode 文字回读和文字溢出结果。
- 禁止对连接线或箭头执行 PowerPoint 的“发送到最底层”或等价的绝对 `SendToBack` / `ZOrder(msoSendToBack)`；该操作会把路径放到填充背景之下并造成箭身在背景区域内消失。连接器只能位于背景之上、节点之下；需要调整时先把背景绝对置底，再相对调整连接器和节点。
- 首次构建只为每个正式公式保留一个无可见文本的唯一命名目标区域；禁止先放普通文本伪公式、公式图片或临时公式对象。
- 骨架确认且唯一权威 PPTX 建立后，一次性识别全部公式并建立 UTF-8 JSON 清单；目标字段必须指向已冻结的幻灯片索引与唯一命名区域。
- 按已确认模式只运行一次内置批处理：Office 模式使用 `../scripts/figure/build_office_manifest.py` 与 `../scripts/figure/run_office_pipeline.ps1`；MathType 模式使用 `../scripts/figure/build_mathtype_manifest.py` 与 `../scripts/figure/run_mathtype_pipeline_sta.ps1`；选择两种都要时，分别生成两个 PPTX，不得在同一公式对象上互相替代。
- PowerPoint 只打开一次，整批公式写入后只保存一次；MathType 模式复用同一个 MathType 进程与编辑器会话，不得为每个公式启动新窗口。不得在内置脚本之外追加全选、输入字母、复制或粘贴等键盘步骤。
- 已确认 MathType 模式时允许且应正常启动一次 MathType；禁止的是复制或粘贴空公式及自动重试造成的循环弹窗，不得把该禁令误解为“禁止启动 MathType”。
- MathType 复制前必须通过内置非空闸门，不能只凭剪贴板格式或 ProgID 判断成功。只有语义字符数为 `0` 或内容真正为空时才停止；只要语义字符数大于 `0` 就允许粘贴，不得自行设置字符覆盖率、对象尺寸或复杂度阈值作为粘贴前阻断条件。禁止自动重试、循环复制或反复弹出 MathType。
- 公式写入前删除对应无可见文本目标对象，完成后每个目标位置只保留一个正式公式对象，并按预留矩形等比例缩放、水平与垂直居中；不得独立拉伸宽度和高度。
- Office 模式必须得到可编辑的 PowerPoint 原生专业公式；MathType 模式必须得到真实 `Equation.DSMT4`。普通文本、图片、空对象和错误公式类型均为交付阻断项。
- 内置公式阶段只核对 `inserted_count` 与公式数一致、输出文件存在且非空，并清理临时 JSON、MathML 与 build 目录；不在该阶段额外生成报告、预览或截图。公式写入完成后，对最终整页统一渲染一次并检查公式区碰撞、裁切和可见内容。
- 默认执行“一次完整生成 → 一次合并审查 → 必要时一次集中修正 → 一次定向复查”。第二次审查后不得继续修改，除非用户明确授权。
- 公式插入、图层顺序和占位符清理属于首次构建步骤，不得延后到审查阶段处理。
- 任何公式插入、文本修改、对象移动、缩放、删除或图层调整都会使此前的视觉审核失效；只能以最后一次修改并保存后的权威 PPTX 作为审核对象。
- 第一次审查后的集中修正必须从 UTF-8 修正清单读取内容，在保存前回读全部受影响对象并重新执行四个保存前闸门。禁止在临时 PowerShell 脚本中直接写入中文整段文本，禁止只为修正标点而重新赋值未受影响的中文。

### 快速构建顺序

#### 0. 冻结已确认骨架

根据文字从零制作时，只能以用户最后一次明确确认的完整骨架作为正式构建输入。先把模块、层级、连接拓扑、分区、主要图标隐喻和公式计划冻结到对象清单，再开始任何 PowerPoint 操作。参考图忠实复刻时，以已确认参数和参考图作为构建输入。

#### 1. 紧凑对象清单

快速记录：

- 页面与主分区；
- 全部文字对象及其角色，并标明是所属 shape 的内部文字还是无框独立文本框；
- 每个独立形状、图片和图标的真实几何、位置、旋转和层级；
- 每条箭头的源、目标、头部数量及所在端、类型、方向、虚实、弧度或拐点；
- 每组应保持水平或垂直直连的框体共享中心轴，以及公式标注所需的独立安全槽；
- 同级重复组件及数量；
- 源图明确存在的包含、覆盖和遮罩关系。

使用稳定 ID 防止漏项即可，不建立额外审查文件。

#### 用户提供素材原样复用闸门

本闸门适用于用户在当前任务中单独提供的 PNG、JPG、SVG、照片、线稿、图标、实验图、局部截图或其他可直接作为一个视觉对象使用的文件。它优先于自动图标生成、矢量描摹、风格统一和 Hybrid Reconstruction 的一般可编辑性偏好。

1. **先登记、后绘制。** 在创建任何相同语义的图标或图片前，建立 `user-asset-ledger.json`，记录源文件绝对路径、用户原话、用途、目标页、目标对象名、是否必须原样使用、允许的几何变换和禁止操作。出现“用这个”“相机用这个”“直接复制”“不要自己生成”等表达时，`reuse_mode` 固定为 `direct_source`。
2. **直接使用源文件。** `direct_source` 素材必须以该文件本身作为独立 PowerPoint 图片对象插入或复制。禁止用 AI 生成图、手绘 SVG、基础形状拼装、轮廓描摹、相似图库图标或重新截图替代；也禁止先生成替代对象，待用户指出后再覆盖在其上。
3. **变换边界明确。** 默认只允许等比缩放和平移。只有语义方向确有需要且用户未禁止时，才允许旋转或水平/垂直镜像，并在素材账本中记录；禁止非等比拉伸、改变线条结构、重新着色、风格化、自动补画或改变内容比例。裁剪只可去除源文件外围纯空白，不得裁去主体或借裁剪改变构图。
4. **可编辑性不得反向覆盖保真。** 用户没有要求重绘或矢量化时，图片作为独立可移动、可缩放对象即满足此素材的编辑边界。框体、箭头、公式和文字仍按原生对象制作，但不得为了让素材内部线条可编辑而自行重画用户素材。
5. **不可用时先停。** 源文件分辨率过低、被文字/水印遮挡、缺失透明背景、主体不完整或无法满足页面尺寸时，先向用户说明具体限制并请求“继续原图 / 授权处理 / 授权重绘”中的方向；未获授权不得静默生成替代版本。
6. **替换必须彻底。** 若错误地创建了替代图形，插入用户源图前必须删除该替代对象及其媒体关系、残留图层和重复对象；禁止同时保留自绘版与源图版，禁止用白色覆盖物隐藏错误版本。
7. **保存前逐项核验。** 对每个 `direct_source` 条目检查：目标页存在且对象数一致、对象使用登记的源文件、宽高比与源文件一致、仅发生已允许的变换、没有自生成同义替代物、最终原生渲染与用户素材可辨识一致。任一项不满足即为交付阻断错误。

典型错误：用户给出相机线稿并说“相机用这个”，却因追求 SVG 可编辑而重新绘制相机。正确做法是直接插入该相机图片；需要表达相反朝向时，仅复制同一源图片并水平翻转，且不得重新生成另一幅相机。

#### 2. 忠实复刻硬规则

- 禁止用“语义相近”或“视觉大致相似”的结构代替源图对象。
- 直线、折线、曲线和块状箭头必须按源图类型复刻，禁止相互降级或替换。
- 椭圆、圆弧、曲线连接器、自由曲线和虚线环必须分别识别；禁止用若干椭圆近似独立曲线箭头。
- 形状轮廓、数量、尺寸关系、旋转、虚实、颜色和层级尽可能按源图还原，不得为了快速绘制擅自改成通用矩形、圆形或直线。
- 原图有箭头头部的连接必须保持为箭头；只有源图明确没有箭头头部时，才允许使用普通线段。
- 箭头头部数量必须按可见形状识别，不得根据“数据下行”“指令上行”“输入”“输出”等语义推断。原图为双头箭头时必须使用双头箭头，不得替换为单头箭头，也不得拆成方向相反的两支单头箭头。
- 禁止根据“层级线”“辅助线”“结构线”等语义判断自行设置 `arrow: false`。
- 图像低清或复杂区域难以辨认时，先局部裁剪放大确认形状和箭头，再绘制；不得直接猜测。
- 单个原生对象无法表达非连接类复杂轮廓时，可使用多个可编辑对象组合还原，但不得改变可见外形和连接语义。此规则不适用于折线和折线箭头；折线类连接必须始终保持为单个 PowerPoint 原生对象。

#### 3. 数值化布局

先确定页面外边距、主分区、行列基线、卡片尺寸和箭头通道。重复组件必须使用共享参数或组件函数批量生成。

先放文本并确定所需空间，再冻结卡片和容器尺寸；不要先画过小的框，再靠缩小字号塞入内容。

直箭头必须先完成框体中心轴对齐，再创建连接器：

- 上下直连的框体使用同一个 `axisX`，按 `left = axisX - width / 2` 排布，使上下边中点的 x 坐标一致；左右直连的框体使用同一个 `axisY`，按 `top = axisY - height / 2` 排布，使左右边中点的 y 坐标一致。
- 连续流程链共用同一条中心轴，不得逐框使用近似坐标。框体宽高不同不影响中心轴对齐。
- 先移动或调整框体、组间距和分区宽度来获得共轴锚点，再连接真实边中点；禁止保留错位框体后让连接器自动生成斜线，也禁止手工拖动箭头端点离开锚点来伪造水平或垂直。
- 直连接器创建函数必须先执行数值断言：水平直连框体中心 y 差、垂直直连框体中心 x 差均须 `≤ 0.1 pt`；断言失败时必须停止创建该连接器并先移动框体。禁止“先生成再看是否倾斜”，也禁止把 `BeginConnected = True` / `EndConnected = True` 当作共轴证明。
- 只要可见框体存在能够保持源图入口、方向和路线的原生连接站点，就必须把连接器端点直接 `BeginConnect` / `EndConnect` 到该可见框体；禁止在真实锚点旁边新建透明小矩形、悬空点或固定坐标端点冒充框体连接，即使两者距离极近或视觉上几乎重合也不允许。
- 仅当源图明确要求框体错位且直线从非中点进入时，才使用绑定到所属框体边界的代理锚点；不得把代理锚点作为不调整排版的默认捷径。
- 为连接器旁的公式或变量预留独立安全槽。垂直箭头的公式放在箭身左侧或右侧，水平箭头的公式放在箭身上方或下方，并与箭身、箭头头部和相邻框线保持至少 `3–4 pt` 的可见间距；空间不足时增加框体间距或调整分区，禁止把公式压在箭身上。
- 公式安全槽账本必须同时记录 `formulaId`、相邻 `connectorId`、所在侧、预计矩形和最小间距。正式公式写入后，用 Office 公式或 MathType OLE 的实际可见外接框替换预计矩形，向外扩展 `3–4 pt` 后与箭身、箭头头部及相邻框线逐项求交；任一相交即停止交付并移动公式槽或框体，不得用公式目标占位框、对象置顶或白底遮盖代替检查。

#### 4. 文字排版

文本角色：

- `TITLE`：页标题、章节标题；
- `SHORT_LABEL`：节点名、栏目名、短标签；
- `BODY_PARAGRAPH`：连续语义正文；
- `BULLET_BODY`：项目符号或编号正文；
- `VERTICAL_LABEL`：源图明确竖排的侧边文字；
- `FORMULA`：公式或变量表达。

硬规则：

- 连续正文必须保持为一个段落，使用文本框自动换行。
- 不得为了平衡行长随意插入硬回车。
- `BODY_PARAGRAPH` 不得居中。
- 中文正文达到三行及以上时默认两端对齐；源图明确左对齐时除外。
- 标题、栏目名、节点名和一至两行短标签可以居中。
- 只有源图明确分行、内容本身是并列短语或不同语义段落时，才保留硬换行。
- 项目符号正文左对齐或两端对齐，并统一悬挂缩进。
- 横排标题、短标签、正文和项目符号文本的任意一行都不得只剩一个汉字、一个英文 token、孤立标点或项目符号；该规则不限于末行。
- 原图允许语义分行时，先验证每个硬换行片段在目标字体、字号、文本框有效宽度和内边距下能完整容纳；不能容纳时不得保留该硬换行方案。
- 文本框有效宽度必须按目标字体在 PowerPoint 中的实际字宽计算，并扣除左右内边距；不能仅依据字符数、生成后端预览或未缩放框宽估算。
- `SHORT_LABEL` 优先保证完整词组同行，例如“评价方法选择”“诊断模式”不能拆成“评价方法选 / 择”或“诊断模 / 式”。
- 同级文本统一字体、字号、字重、行距、内边距、方向和对齐。

文字修复顺序：

1. 删除造成孤字或孤立 token 的非必要硬回车；
2. 扩大文本框有效宽度或减小左右内边距；
3. 同步扩大卡片并调整相邻模块、箭头通道和间距；
4. 在用户允许范围内统一调整同级字号，但不得低于用户下限；
5. 必要时扩大所属区域或调整整体布局；
6. 完成后在最终 PowerPoint 渲染中重新确认实际换行。

不得只缩小一个同级卡片的字号，也不得用自动缩字、继续添加硬回车或拆散词组来掩盖错误断行。若消除单字行与同级等宽、原框宽或局部对齐冲突，优先消除单字行。

#### 5. 形状与留白

- 页面外边距通常为短边的 4%–6%，参考图更紧时按原图。
- 普通模块间距约 4–8 pt；高密度区域不低于约 3 pt。
- 正文内边距通常为 4–8 pt；高密度卡片可用 3–5 pt。
- 文字框和模块框按最终可见字形计算。字形到上、下、左、右边界均至少保留当前字号的 `0.5×` 作为安全距离；普通紧凑框的各向留白通常不超过 `1.0×`。低于下限时扩大有效文字区或框体，高于上限时缩短框高、收紧段前段后与行距或重排；不得通过放大字号、增加说明文字或保留空行填充。
- 同级卡片优先保持等宽、等高、等间距；若与消除单字行冲突，先扩大整组卡片或重分配列宽，不得保留单字行。
- 为标题、正文、箭头通道和底部输出区分别预留空间。
- 为每个正式公式预留按预计可见尺寸计算的公式槽和 `3–4 pt` 安全边界；连接器标注公式的公式槽不得与箭头通道重叠。
- 页面不得一侧拥挤、一侧空洞。
- 大框、虚线容器和分区内若出现宽度或高度超过相邻模块尺寸 `0.5×` 的连续大片空白，视为自动重排触发项：保持逻辑和复杂模块内部比例不变，重新分配整组模块的宽高、位置与等距间隔，直至内容充实且均衡；禁止用正文式描述、冗余标签或装饰性空框填补。
- 源图中的正常包含、标题条嵌合、图标覆盖和遮罩不是碰撞。

#### 6. 箭头

模块位置冻结后再生成箭头。每条箭头只选一种实现：

| 类型 | 实现 |
|---|---|
| `LINE_ARROW` | 原生直线连接器或线条箭头 |
| `ELBOW_CONNECTOR` | 原生肘形连接器 |
| `CURVED_CONNECTOR` | 原生曲线连接器 |
| `BLOCK_ARROW` | 原生块状箭头形状 |

规则：

- 创建水平或垂直直箭头前，先验证相连框体的目标边中点已经共轴：水平直连要求框体中心 y 一致，垂直直连要求框体中心 x 一致。未共轴时先调整框体排版，禁止直接生成连接器。
- 每条折线和折线箭头只能使用一个 PowerPoint 原生可编辑对象：优先使用原生肘形连接器；需要锁定多个拐点时，使用一个原生自由曲线/自由多段线形状并在同一对象的线条属性中设置箭头端点。禁止拆成多条直线或多支箭头，禁止以组合、成组或视觉对齐掩盖拼接。
- 折线对象完成后必须在 PowerPoint 对象层级中核对：一条逻辑路径对应且只对应一个对象；不得存在同一路径的 `_SEG_`、分段线或首尾相接的多个线条对象。
- 保持源图的箭头数量、类型、方向、虚实、颜色、头部位置和实际路径。
- 将箭头头部数量作为几何属性逐条记录：`0`、`1` 或 `2`。双头块状箭头优先使用对应原生双头形状，例如垂直双头箭头使用 `upDownArrow`；不得用 `upArrow`、`downArrow` 或语义方向替代。
- 箭头的连接拓扑属于源图内容，不得改变。逐条记录并保持 `源对象 → 中间节点/分支 → 目标对象`；不得跳过节点、交换源与目标、改接邻近对象、合并分支或凭语义重新连接。
- 每条箭头必须记录 `sourceId`、源端锚点所在边及相对位置、全部拐点或曲线控制点、`targetId`、目标端锚点所在边及相对位置、箭头头部所在端。生成时按该记录逐项复刻，不得仅记录“两个对象相连”。
- 连接锚点必须与源图一致：上边、下边、左边、右边、角部或边上的偏移位置均不得擅自改变。禁止使用自动就近锚点、默认中心点或中心到中心连线代替源图锚点。
- **优先建立真实锚点连接。** 当一条箭头单独进入或离开矩形、卡片或其他带连接站点的可见模块，且对应边中点能够保持源图方向与路线时，必须用 PowerPoint 原生连接器的 `BeginConnect` / `EndConnect` 连接到该可见形状的真实边中点；禁止把端点停在距离框线仍有可见缝隙的自由坐标或悬空代理点。
- “连接成功”同时要求连接状态和连接目标身份正确。若账本规定端点应连接可见框体，则 `BeginConnectedShape` / `EndConnectedShape` 必须就是该框体对象；连接到邻近透明代理形状、其他框体或任意对象后仅得到 `BeginConnected=True` / `EndConnected=True`，一律判定为错误连接，禁止通过审计。
- `Background < shapes < icons < text` 只描述最终 Z 序；不得据此推导“必须先创建连接器再创建节点”。节点应先存在并成为连接目标，连接器创建后再执行相对 Z 序调整。
- 锚点实现优先级固定为：`两端真实可见形状锚点` → `一端真实锚点 + 一端贴边代理锚点` → `两端贴边代理锚点`。只有前一级会改变源图入口、造成多路箭头重叠、自动错误改道或产生斜线时，才允许降到后一级。
- 不得为了“两端都是真实中点锚点”牺牲源图的水平、垂直或直角路径。若两个框的边中点不共轴，而源图为水平或垂直直箭头，必须先调整框体位置使中心轴对齐；只有源图明确要求框体错位或调整会破坏已确认结构时，才保留能够自然连接的一端为真实中点锚点，另一端使用位于可见框线上的代理锚点，使直线仍满足 `≤ 0.1 pt` 的水平/垂直误差。禁止强连两个不共轴中点后得到无源斜线。
- 同一边存在多个独立入口、分支入口或偏移入口时，不得把它们全部吸附到同一个中点而合并或重叠。按源图保留各自入口；无法用真实连接站点表达的入口使用贴边代理锚点。代理锚点中心必须精确位于可见边框上，尺寸足够小且完全不可见，随所属模块同步移动，箭头端点与框线不得出现肉眼可见缝隙。
- 代理锚点不是自由悬空端点：连接器端必须实际连接到该代理形状；代理形状必须绑定到明确的所属模块和边。工作记录中区分 `visible_shape_anchor` 与 `border_proxy_anchor`，不得用“已连接”笼统掩盖代理点仍离开框线。
- 每个代理锚点必须进入显式白名单，记录 `connectorId`、端点、所属可见模块、所属边、边上相对位置及无法使用真实连接站点的具体原因。没有原因、仅为编程方便、仅为保持固定坐标或位于可用真实锚点附近的代理锚点均为禁止项；`unjustified_proxy_anchor_count` 必须为 `0`。
- 所有获准代理锚点必须通过“不保存移动跟随测试”：在临时只读/不保存会话中移动所属可见模块至少 `5 pt`，验证代理锚点和连接器端点同步移动，再撤销或关闭不保存。未同步即为悬空代理，禁止交付。
- 修改现有 PPT 时，先从 PowerPoint 原生对象读取每条连接器的 `BeginConnected`、`EndConnected`、`BeginConnectedShape` 和 `EndConnectedShape`；能改接到可见模块真实连接站点的端点直接改接，不能改接的端点移动原代理锚点到框线。保存后要求所有逻辑连接器两端均处于已连接状态，未连接端点数必须为 `0`。
- 原图为水平段时，端点和该段全部拐点必须保持同一 y；原图为垂直段时必须保持同一 x。原图为水平/垂直直角折线时，只能使用水平段和垂直段，禁止因对象错位改成斜线。
- 对参考图中的水平直箭头和水平线段，最终 PPT 对象检查必须满足起点与终点纵坐标差 `|y1-y2| ≤ 0.1 pt`；垂直直箭头和垂直线段必须满足 `|x1-x2| ≤ 0.1 pt`。超过阈值即为斜线和交付阻断项，不得凭肉眼认定“基本水平/垂直”。
- 若对象位置导致原路径无法保持水平或垂直，先修正对象位置、尺寸或锚点；不得让箭头路径迁就错误布局。
- 若原生肘形连接器会自动改锚点或改道，先使用随目标同步移动的不可见代理锚点；仍无法锁定原图路线时，改用一个 PowerPoint 原生自由曲线/自由多段线对象承载全部拐点，并在该单一对象上设置箭头头部。不得使用分段原生线条。
- 在创建反馈折线前先根据源图冻结完整正交路径和外侧通道，逐段检查是否穿过节点、文字、公式与相邻箭头。若所需段数或拐点数超过 PowerPoint 原生肘形连接器能够稳定保持的路径，直接使用一个原生自由多段线对象；禁止先反复试改肘形连接器、在模块内部来回穿越后才切换实现。
- 肘形连接器存在 `flipH`、`flipV` 或端点方向翻转时，`Adjustments.Item(n)` 使用连接器局部几何坐标，不等同于幻灯片的绝对左右/上下方向。设置调整值前必须读取翻转状态、OOXML 预设几何或渲染后的折点位置；禁止仅凭正负号猜测折点方向，禁止把未经验证的调整值直接保存到权威 PPTX。
- 自由多段线、自由曲线和普通线条同样属于逻辑箭头路径。最终路径统计必须覆盖原生连接器、自由多段线、自由曲线和线条箭头，形成统一的 `logical_path_count` 与逐条对象名；不得只统计 `Shape.Connector = True` 的对象后声称箭头完整。
- 曲线箭头必须使用可编辑曲线连接器或可编辑组合曲线路径，保持弧向、弯曲程度和连接边界；不得改成直线、折线或椭圆。
- 原图每个箭头头部都必须显式记录并生成。不得因为连接位于第二层、容器内部或重复组件中而关闭箭头。
- 批量组件只能复用已核对的箭头配置；不得让通用组件凭层级自动决定 `arrow: false`。
- 箭头必须指向语义目标，不得落在文字、装饰或邻近对象上。
- 水平路线保持同一 y，垂直路线保持同一 x。
- 折线路线使用水平/垂直段；反馈箭头优先走模块外侧。
- 箭身必须可见并明显长于箭头头部。`0.9–1.3 pt` 的普通细线默认配窄型、短型实心三角头；只有参考图和通道尺度同时需要时才使用中等或更大头部。必须联合回读线宽、`Begin/EndArrowheadStyle`、`Begin/EndArrowheadWidth`、`Begin/EndArrowheadLength` 并查看最终渲染，禁止仅凭“有箭头”通过。
- 固定逻辑连接区域的图层顺序为 `Background < shapes < icons < text`：背景先生成；原生连接线、箭头、曲线、节点、模块和因子统一归入 `shapes`，有框模块文字作为所属 shape 的内部文本随该对象存在；只有确属图标的独立对象才进入 `icons`；`text` 层仅放无所属外框的标题、列标题、注释、图例文字和公式说明。禁止把有框模块拆成“框体 + 覆盖文本框”，禁止把连接器绝对置底，也禁止把可由内置形状完成的对象转成 SVG。
- 任何公式插入、占位框清理、节点移动或局部修复后，都要重新确认带填充背景仍为最低可见层。不能因为公式或节点仍可见就认定图层正确；只要箭身进入底色区域后消失、变短或断裂，即判定为背景遮挡阻断项。
- 箭头穿过节点框仅在源图确实如此时保留，但路径仍不得覆盖节点文字。不能依赖连接器“默认置底”；普通线段、组合箭头和后生成路径必须显式核对层级。
- 只有源图明确要求路径显示在模块内部或文字之上时，才提高对应路径层级，并只提高该条路径。
- 使用当前后端已经确认的端点语义。若 `head` 位于源端、`tail` 位于目标端，目标箭头直接使用 `tail`，不要反向绘制后旋转。
- 必要时可使用位于目标可见边界上的不可见代理锚点，但必须随目标同步移动。

### 碰撞原则

文字和公式碰撞是最高优先级交付阻断项。所有文本和公式必须按 PowerPoint 最终渲染后的实际可见边界判断，而不是只看文本框、公式目标占位框、后端估算或对象层级。Office 原生公式按实际可见字形判断，MathType 按最终保存后的 `Equation.DSMT4` OLE 可见边界判断。文字或公式与所属容器是正常包含关系，但可见内容不得接触或穿越容器边框。

必须消除：

- 任何标题、标签、正文、项目符号、公式说明或正式公式与框线、箭身、箭头头部、形状、图标、图片、其他公式或其他文字相交；
- 作为连接器标注的公式覆盖箭身、箭头头部或相邻框线；公式必须位于箭身侧边的独立安全槽，不能以白底、置顶或 OLE 外框遮住连接器；
- 箭头穿过文字或无关模块；
- 两个独立卡片、图标、公式、块状箭头或图片互相侵入；
- 内容越出页面或所属区域；
- 同级对象间距明显不一致。

判断时将文字、公式和箭头的可见边界向外扩展约 3–4 pt，保留视觉安全距离。文字和公式不得通过置顶、遮罩、白底覆盖或把路径置底来“视觉隐藏”碰撞；如果几何上仍相交，就必须调整文本框、公式槽、容器尺寸、框体中心轴、对象位置、模块间距或单条原生折线路径。

旋转块状箭头、曲线箭头和组合路径必须按旋转后的实际可见轮廓判断碰撞，不得只使用未旋转外接框或对象中心距离。

忽略正常容器包含、源图明确存在的标题条叠放、嵌入、遮罩和有意覆盖。碰撞豁免必须对应到源图中的具体对象对和具体交叠范围；源图某处存在交叉，不代表该区域内的所有重叠都可以忽略。不要为消除工具误报而移动已经正确的对象。

发现碰撞时优先扩大文本框或容器、增加内边距、移动独立对象或扩大箭头通道；不得通过删除箭头、改写文字、乱断行、单独缩小字号、改变层级或拼接折线解决。

### 可编辑性

- 文本、形状和逻辑箭头必须是独立可编辑对象。
- 不得把整张参考图作为背景或整页截图交付。
- 实验图、显微图和照片可作为独立裁剪图片嵌入。
- 只保留一个权威 PPTX。

### PowerPoint 公式写入

正式 PPT 存在公式时，执行本 skill 的内置公式流水线，不得读取其他公式 skill 或恢复历史 MathType SOP：

1. 在进入公式写入前，确认公式类型、目标 PPTX 完整路径和分页形式已随整份参数清单得到用户明确确认。
2. 在唯一权威 PPTX 中为每个公式建立无可见文本的唯一命名目标形状，冻结幻灯片索引、目标名称、矩形和公式顺序。
3. 一次性识别全部公式为 LaTeX，保持原顺序、上下标、分式、矩阵、分段、重音、粗体和公式编号，并将稳定 ID、原编号、页码和目标写入一份临时 JSON；无法可靠辨认的公式标记“待核对”，继续处理其余公式。
4. 公式 JSON 使用 UTF-8，基本结构为 `{"equations":[{"latex":"...","page":1}]}`；可按需加入稳定 `id`、原编号和 `target`。仅当 PDF、旋转或分辨率问题影响识别时才使用 `../scripts/figure/prepare_sources.py`。
5. Office 模式先运行一次 `../scripts/figure/build_office_manifest.py`，再运行一次 `powershell -NoProfile -ExecutionPolicy Bypass -File ../scripts/figure/run_office_pipeline.ps1 -ManifestPath <manifest> -OutputPath <pptx>`。
6. MathType 模式先运行一次 `../scripts/figure/build_mathtype_manifest.py`，再运行一次 `powershell -NoProfile -ExecutionPolicy Bypass -Sta -File ../scripts/figure/run_mathtype_pipeline_sta.ps1 -ManifestPath <manifest> -OutputPath <pptx> -BuildDir <build>`。
7. Office 模式写入可编辑的 PowerPoint 原生专业公式；MathType 模式写入真实 `Equation.DSMT4`；两种都要时分别写入两个 PPTX。
8. 只接受 `inserted_count` 与公式数量相等且目标文件存在、非空的结果。失败时只报告具体公式与失败阶段，不得声称整批完成。
9. MathType 自定义剪贴板必须包含 `MathML Presentation`，内容为 UTF-8 字节加一个 NULL；按下粘贴前必须反向读取并确认格式存在、UTF-8 可解码且含非空 `<math>`。只拦截语义字符数为 `0` 的真正空公式；非零内容允许粘贴。
10. 每个 MathType 公式按“先准备编辑区 → 写入当前 MathML 剪贴板 → 立即粘贴 → 清空输入剪贴板 → 从 MathType 复制 OLE → 立即粘贴到 PowerPoint”的完整事务顺序执行；OLE 剪贴板生成后不得插入窗口切换、阶段日志写入或布局计算。写入剪贴板前必须解析 XML，拒绝空的 `mi`、`mo`、`mn`、`mtext` token 和语义字符数为 0 的公式，禁止把空公式交给 MathType。单个公式在普通剪贴板竞争时允许最多 3 次有界事务重试；一旦出现“MathType 错误：剪贴板未含有公式数据”窗口，立即向该模态框发送一次 Enter，关闭窗口并退出当前公式的重试 circle，不得对同一份未修改 MathML 再次粘贴；记录该公式为待修正并继续整批其余公式。缺少 `MathML Presentation`、剪贴板回读格式不符合预期、被截图程序等外部应用覆盖或等价情况只表示该次事务待重试，不得据此宣称公式内容或 MathType 公式失败。只有无法生成非空 `Equation.DSMT4`、粘贴对象类型错误、对象为空或越界、或最终对象数不匹配时，才定义为公式写入失败。批次结束后保存全部已写入对象，再对待重试清单修正输入后重新测试；禁止对同一未修改输入无限循环或反复弹窗。
11. 写入后读取每个公式对象的实际尺寸和最终可见内容；若侵入箭身、箭头头部、框线、文字、其他公式或形状，优先调整相邻框体、公式槽和箭头通道，不得只缩小单个公式掩盖布局错误。
12. 清理临时 JSON、MathML 和 build 目录后，从最终保存的权威 PPTX 进行唯一一次整页渲染和公式区视觉检查。

### 最终状态检查闸门

只有全部内容、已确认类型的正式公式对象、图层和局部修复均已写入并保存到唯一权威 PPTX 后，才允许开始最终检查。生成器预览、修复前截图、对象数量、后端布局估算和 PowerPoint 编辑窗口缩略图均不能替代最终保存状态的 PowerPoint 渲染。

从最终保存的 PPTX 渲染全页一次，并从同一最终状态局部放大所有窄标签框、高密度文本、交叉箭头、旋转块状箭头、公式区和粗路径穿过节点区域。高密度区域必须按 100%–200% 视觉尺度检查实际字形边界，不能只看整页缩略图：

- 是否存在任何横排单字行、单个英文 token 行、孤立标点行或项目符号独占行；存在任意一处即为交付阻断项，必须优先修复；
- 是否存在任何文字或公式与容器边框、框线、箭头、连接线、形状、图标、图片、其他公式或其他文字的碰撞；逐个高密度文本框和正式公式按实际可见边界与 `3–4 pt` 安全距离检查，MathType 必须读取最终 `Equation.DSMT4` OLE 的实际边界，不能使用目标占位框代替；存在任意一处即为最高优先级交付阻断项；
- 正文是否保持完整段落，三行及以上是否正确两端对齐；
- 是否存在溢出、孤行、异常字号或同级格式不一致；
- 箭头是否逐条存在，头部数量、头部位置、方向和目标是否正确；双头箭头是否被误画为单头箭头或两支单头箭头；
- 直线是否笔直，曲线是否保持原图弧向和弯曲程度，折线拐点是否对应，且均不穿字；
- 每条折线和折线箭头是否为且仅为一个 PowerPoint 原生可编辑对象，是否存在分段线、首尾拼接、组合拼接或 `_SEG_` 对象；存在任意一处即优先纳入第一次审查后的集中修正，仅在已完成第二次审查时允许记录后按上限交付；
- 是否存在用普通线段替代箭头、用椭圆替代曲线箭头或用通用形状替代特殊轮廓；
- 每条箭头的源对象、目标对象、中间节点、分支关系和头部所在端是否与源图一致；
- 每条箭头的源端锚点、目标端锚点、边上偏移位置和拐点是否与源图一致；原图水平/垂直的线段是否仍严格水平/垂直，是否出现无源斜线；
- 对所有指向或离开可见框体的箭头，是否已在不改变源图路线的前提下尽可能连接到真实边中点；其余代理锚点中心是否精确落在可见框线上，箭头与框线是否存在可见缝隙；是否错误地强连不共轴中点而制造斜线；
- 从最终保存的 PowerPoint 原生对象统计 `visible_shape_anchor`、`border_proxy_anchor` 和未连接端点数量；未连接端点必须为 `0`，代理锚点必须有明确所属模块与边，且所有连接器的 `BeginConnected` / `EndConnected` 均为真；
- 对照逐条连接账本核对 `BeginConnectedShape.Name` 与 `EndConnectedShape.Name`：规定连接可见框体的端点必须命中预期框体名称，规定使用代理锚点的端点必须命中白名单中的唯一代理名称及所属框体。单列 `anchor_target_mismatch_count` 和 `unjustified_proxy_anchor_count`，两者必须为 `0`；禁止以“端点已连接”“距离锚点很近”或“视觉无明显缝隙”替代连接目标身份检查；
- 对最终保存的 PPTX 运行 `../scripts/figure/audit_pptx_connector_contract.py --input <pptx> --ledger <connector-ledger.json> --output <connector-audit.json>` 并保存结构化结果。该脚本为全部 PPT 任务的主连接器审计；必须退出码为 `0` 且 `ok=true`。账本缺失、连接器数量不符、未连接端点、目标不匹配、未授权代理、未登记普通线条箭头、共轴路径使用折线、几何类型不符、逻辑路径重复或分段对象任一非零即为交付阻断项；
- `audit_connector_target_identity.py` 只可作为兼容性补充检查，不得替代主连接器审计。自由多段线/自由曲线路径仍须由统一逻辑路径账本核对其单对象性、碰撞、越界和 Z 序；
- 对源图全部水平/垂直箭头形成逐条几何账本，并从最终保存的 PowerPoint 原生对象读取端点验证：水平对象 `|y1-y2| ≤ 0.1 pt`，垂直对象 `|x1-x2| ≤ 0.1 pt`；不得只查看整页渲染或连接器外接框；
- 对每组水平或垂直直连框体读取最终框体坐标，验证水平直连框体中心 y 差和垂直直连框体中心 x 差均 `≤ 0.1 pt`；超差时应在唯一一次集中修正中先调整框体排版并重新连接锚点，不得只拖动箭头端点；
- 最终几何账本必须单列 `formula_connector_collision_count` 与 `non_axis_aligned_straight_connector_count`，两者都必须为 `0`。碰撞计数使用正式公式实际可见边界扩展 `3–4 pt` 后与连接器路径/箭头头部的求交结果；斜线计数使用最终端点坐标和直连框体中心轴坐标。仅有公式数量正确、对象未越界、连接器数量正确或两端已连接，均不得替代这两个零值断言。
- 将普通连接器与自由多段线/自由曲线共同纳入碰撞、Z 序、越界和对象唯一性检查；`unconnected_connectors = 0` 只证明普通连接器端点状态正确，不能证明自由路径未漏计、未穿框或未碰撞。
- 从最终保存的 PowerPoint 原生对象读取 Z 序，形成最小图层账本：每个带填充背景的 Z 序必须低于其区域内全部连接器、箭头、节点、文字和公式；每条连接器必须高于对应背景且低于节点与公式。禁止仅凭缩略图或“背景已调用 SendToBack”推断图层正确。
- 对参考图逐区域颜色与填充账本执行覆盖核对：每个闭合区域、分区底板、研究面板、标题条和带底色容器均须存在对应对象，且 `fill_mode`、填充色、边框色、透明度和文字色均已显式赋值。缺少整块填充或把近白色误作无填充属于结构性漏项，必须纳入集中修正，不得归入轻微色差。
- 审计计数必须由最终对象和实际几何计算得到，禁止把 `formula_connector_collision_count`、未连接端点数、斜线数、图层违规数或其他结论硬编码为 `0`。尚未实现的检查必须输出 `null`/`not_checked` 并视为未通过，不能伪装成零阻断。
- 禁止使用真空通过：预期存在逻辑连接器时，`connector_count = 0` 不能与 `unconnected_connectors = 0` 合并解释为“连接器全部正常”；必须先核对预期对象数、实际对象数和审计覆盖对象数一致。
- Z 序按对象间相对关系判断，不使用固定绝对层号阈值。公式目标框、后插入 OLE 或其他隐藏对象改变绝对层号时，只要仍满足 `背景 < 路径 < 节点 < 文字/公式` 就不算违规；反之即使背景层号很小，只要高于对应路径仍判定违规。
- 放大检查每条穿过底色区域的箭身是否从进入背景到离开背景全程连续可见。背景遮住任意箭身、箭头头部、公式或文字均为交付阻断项。
- 连接线和箭头是否位于节点形状之下，有框节点文字是否随所属 shape 正确显示、无框独立文本框是否位于最上层，是否存在粗路径压住文字；
- 独立模块是否真实碰撞；
- 旋转块状箭头、对向箭头和循环箭头之间的交叠是否仅保留源图明确存在的范围，是否侵入相邻循环、文字或无关形状；
- 页面边距、模块间距、文本内边距和整体视觉重量是否均衡；
- 参考图中的模块、文字、形状、曲线和箭头是否有漏项、简化、替换或无源新增；
- PPTX 是否非空，主要对象是否仍可独立编辑。
- 公式对象数量是否与公式清单一致；Office 模式是否为 PowerPoint 原生专业公式，MathType 模式是否全部为非空 `Equation.DSMT4`，两种都要时两个 PPTX 是否分别满足各自对象类型；是否存在普通文本、图片或空对象冒充公式。

在工作记录中形成最小审核账本：权威文件路径、最后保存时间、公式模式、公式数量与对象类型、MathType 模式下的 `ProgID`、已放大检查的高密度区域、颜色/填充覆盖计数、当前审查次数、是否因完成第 2 次审查而停止、阻断项数量。只有阻断项为 `0` 才允许使用“已审核”“阻断项为 0”“严格通过审核”等表述；第 2 次审查后仍有问题时仍须交付，但必须标记为“第二次审查后按上限交付当前版本”并说明残留问题。

若第 1 次合并审查发现问题，只修复影响阅读、颜色/填充覆盖、方向、结构或可编辑性的对象；先汇总后在一个写入会话集中修正并保存一次。修正后重新渲染受影响区域；若修改影响全局布局、公式、字号、图层、区域底色或页面尺寸，则重新渲染全页，并将其作为第 2 次定向审查。任何审查后的再次修改都会使审核账本失效；第 2 次审查后即使仍发现问题，也只记录而不再修改，并立即交付当前版本，除非用户明确授权继续。

单字行和孤立 token 始终属于明显问题，必须在唯一一次集中修正中优先处理；第 2 次审查后仍存在时，将其写入残留问题并按上限交付。轻微色差、亚像素间距、截图压缩和非关键装饰差异不阻断正常交付，但整块填充缺失、有色区域被设为无填充或沿用错误主题色不属于轻微色差。

#### 验证器结果判定

- 同时依据进程退出码、结构化输出和产物状态判定验证结果。验证器或包装器返回非零退出码时，先检查其结构化输出是否已给出正确页数与输出路径，并验证渲染文件真实存在、非空且可读取；产物有效时记录为“包装器退出码异常”，不得误报为 PPTX 渲染失败。反之，退出码为 `0` 但要求的文件缺失或为空时仍判定失败。
- 错误路径若把 `.cache\codex-runtimes` 拼到当前工作目录下，按“运行时根目录推导错误”处理，禁止不改变环境与参数就重复执行同一命令。改用依赖发现结果、显式工作区或能够正确解析用户运行时根目录的执行位置后，只重试一次。
- PowerPoint 原生最终渲染与对象审计是 PPTX 状态的裁决依据；通用验证器用于补充检查，不能以自身环境初始化失败、包装器退出码异常或不支持 MathType OLE 为由否定已验证的 PowerPoint 原生结果，也不能掩盖原生检查发现的真实碰撞、斜线或对象缺失。

### 交付

在第 `1` 次合并审查阻断项为 `0`，或已完成第 `2` 次定向审查后，交付当前可编辑 PPTX。最终回复简要说明文件、页面尺寸、字体和可编辑性；包含公式时，同时给出“已写入数量 / 待核对数量”。达到审查上限但仍有问题时，必须说明“第二次审查后按上限交付当前版本”并列出主要残留问题；未形成零阻断审核账本时，不得声称已完成审核。

### 1. 适用范围与优先级

本文件适用于本 skill 执行的全部 PowerPoint 任务，包括：

- 从文字、论文、Word、提纲或数据创建 PPT；
- 根据参考图忠实复刻；
- 修改、翻译、统一或优化已有 PPT；
- 增加模块、公式、箭头、曲线、图例或复杂图形；
- 局部修正、重新排版和最终交付。

所有任务默认执行本文件，不得因为任务简单、时间紧、已有模板或只改一处而跳过。

质量优先级固定为：

1. 内容、逻辑和参考来源正确；
2. 文字、公式、箭头和图形零碰撞；
3. 对象类型和连接拓扑正确；
4. 原生可编辑性与复杂模块比例保护；
5. 水平、垂直、锚点、图层和路径正确；
6. 文字完整、无孤字、无溢出；
7. 留白、密度、对齐和视觉平衡；
8. 配色、装饰和次要风格细节。

用户明确要求的参数值高于推荐值，但不能取消零碰撞、可编辑性、内容正确和路径类型忠实等硬门槛。参考图中明确存在的特殊排版可以作为例外，但必须记录具体对象和例外范围，禁止泛化。

### 2. 用户参数与参考来源

1. 页面尺寸、方向、宽高比、字体、字号范围、配色、输出文件和分页方式均由当前任务参数决定，不设跨任务默认值。已有 PPT 还必须分别确认文件动作与页面动作：原页直接修改、原 PPT 内新增页、原 PPT 内复制页后修改、另存整个 PPT 副本；不得把前 3 项自动转换为第 4 项。
2. 每次 PPT 创建、复刻、翻译、优化或修改任务都必须显式询问并确认“比例是什么样的”。不得因为已有模板、参考图、用户只要求改风格或任务看似简单而省略。确认问题必须覆盖：
   - 保持源 PPT/源图中全部对象的原始宽高比和相对几何，还是采用新的比例；
   - 若采用新比例，具体数值或范围及允许误差；
   - 比例作用对象：页面、主图体、指定区域、对象组或单个模块；
   - 是否允许等比缩放；若允许，是否保持原始尺寸还是只允许统一缩放因子；
   - 是否要求填满页面、适度放大，或允许保留源图留白。
3. 宽高比必须同时记录：
   - 数值或范围；
   - 允许误差；
   - 作用对象：页面、主图体、指定区域或指定模块；
   - 是否保持源模块比例。
4. 比例策略未获得用户明确回复时实行失败关闭：只允许汇总参数并等待，不得开始正式分析、创建骨架、打开写入会话或修改 PPT。
5. “改成某图风格”“沿用某图配色”“参考某图”只授权修改用户明确指定的视觉属性，不授权改变源对象尺寸、宽高比、位置、组内相对坐标、连接拓扑或页面占用率。需要改变上述任一几何属性时，必须单独列出并重新确认。
6. 用户要求“保持原比例”时：
   - 冻结源对象和复杂模块的 `width/height`；
   - 冻结对象组内部相对坐标、间距、旋转、连接点和图标比例；
   - 未另行授权时保持原始尺寸，仅允许整体平移；
   - 用户允许缩放时只能统一等比缩放，横纵缩放因子必须相等；
   - 不得把圆改成椭圆、把椭圆改成圆，或为了适应页面重新排列成新的环形、矩阵或流程布局。
7. 用户要求“不用填满页面”时，源图正常留白属于冻结视觉结构。不得触发“大片空白自动重排”，不得放大主图体填充 A4，也不得用新增文字、装饰或拉伸对象填空。
8. 页面宽高比、主图体宽高比和源模块宽高比是三个独立参数。A4、16:9 或其他页面尺寸不得自动成为主图体或模块比例。
9. 不得沿用上一次任务的比例、字体、颜色、公式类型或页面设置。
10. 参考图任务以参考图的可见几何为准；已有 PPT 任务以源 PPT 原生对象为准；论文驱动任务以论文内容为逻辑最高原则。
11. 同一任务存在多种来源时，先冻结各自职责：
   - 论文或正文决定内容与逻辑；
   - 源 PPT 决定对象、视觉和模板；
   - 用户最新确认决定取舍和参数。
12. 未经用户授权，不修改未纳入范围的页面、模块、公式、颜色、线型或连接关系。
13. “在原 PPT 新建一页”只改变原 PPT 的页集合，不产生第二个 PPTX；“保留原页再改”默认在原 PPT 内复制源页并紧随其后插入。只有用户明确要求另存时才生成整个演示文稿副本。

### 3. 页面、网格与整体布局

1. 先确定页面边界、外边距、主图区域、标题区域、底部说明区和各主分区，再放置细节对象。
2. 使用共享行列网格、中心轴和基线；重复组件必须使用同一组尺寸、间距和对齐参数。
3. 页面不得一侧拥挤、一侧空洞。主内容应均匀覆盖确认的图体区域，并保持明确视觉中心。
4. 大框、虚线容器或分区中出现连续大片空白时，只有用户已确认“允许优化页面占用率”才可在保持复杂模块内部比例不变的前提下重新分配完整模块的位置、尺寸和间距。
5. 当用户已确认允许优化页面占用率时，连续空白的宽度或高度超过相邻模块对应尺寸的 `0.5×` 才触发自动重排；用户要求保持原比例、保持原布局或不用填满页面时，本规则不触发，必须保留源图正常留白。
6. 同级模块优先等宽、等高、等距；若与文字完整性冲突，优先扩大整组或重分配列宽。
7. 普通模块间距通常保持 `4–8 pt`，高密度区域不得低于约 `3 pt`；参考图更紧或用户另有设置时按确认值。
8. 图体比例调整通过外围分区和完整模块重排实现，禁止非等比拉伸复杂模块或单独压缩局部元素。
9. 任何版式优化都不得改变已经确认的内容层级和连接拓扑。

### 4. 字体与文字排版

1. 凡文字位于可见模块框、节点、圆形、色条或标签卡内部，必须写入该 PowerPoint 原生形状自身的 `TextFrame/TextFrame2`；框体与文字必须是同一个对象。禁止另建独立文本框覆盖在形状上。只有没有所属外框的标题、列标题、注释、图例文字和公式说明允许使用独立文本框。
2. 字体和字号必须在当前用户确认范围内；不得使用历史任务中的固定字号。
3. 标题、模块名、正文、图例和公式说明按角色分级，但同级对象必须统一字体、字号、字重、行距、方向和对齐。
4. 先按最终字体和字号测量实际字形，再确定形状文本区或独立文本框；禁止先画过小的框，再用自动缩字塞入。
5. 任何横排文本不得出现：
   - 单个汉字独占一行；
   - 单个英文 token 独占一行；
   - 孤立标点；
   - 项目符号单独一行。
6. 不得为追求行长平衡随意插入硬回车。优先使用自动换行、扩大有效宽度或调整整组模块。
7. 短标签优先保持完整词组同行；不得拆散术语、模块名和固定短语。
8. 三行及以上中文正文默认两端对齐，除非参考图或用户明确要求左对齐。
9. 系统框图、技术路线图和因子图只放模块名、约束名和必要短语；正文式机制说明放在论文或演示正文，不塞入框图。
10. 不得只缩小某一个同级文本框的字号来解决碰撞；应先扩大文本框、调整边距、卡片或整组布局。
11. 所有文字以 PowerPoint 最终渲染后的实际可见字形为裁决依据，不能只看文本框边界。

### 5. 文本框、模块框与留白

1. 有框模块使用形状自身文本区；独立文本框只用于无所属外框的文字。两者都必须给文字保留安全内边距，但不得形成松散空壳。
2. 对含文字的可见模块框，最终字形到上、下、左、右边界均至少保留当前字号 `0.5×` 的安全距离；普通紧凑框通常不超过 `1.0×`。低于下限时扩大有效文字区或框体，高于上限时收紧框高、行距、段前段后或重新布局。
3. 大框包含小框时，四周连续留白不得超过相邻最小子模块对应尺寸的 `0.5×`；超过即重新分配子模块。
4. 文字与所属容器是正常包含关系，但实际字形不得接触或穿越容器边框。
5. 模块框不得因内容少而保留大片空白，也不得因内容多而压住文字或箭头通道。
6. 标题条文字直接写入标题条形状；标题条与内容区必须分槽，禁止用独立标题文本框覆盖整个模块后再叠放正文或公式。
7. 正文内边距通常为 `4–8 pt`，高密度卡片可为 `3–5 pt`；若用户设置更严格，以用户值为准。
8. 框内存在图标、公式或子图时，分别预留独立槽位，禁止相互覆盖。
9. 圆角、直角、边框粗细和填充必须沿用参考或模板；不得把无圆角框擅自改成圆角框。

### 6. 直线、箭头与连接器

本节的对象类型、真实锚点、直线/折线判定、代理例外、账本字段和失败条件统一服从 [PPT 连接器强制契约](figure-workflow.md)。该契约适用于全部 PPT 任务并高于工具默认连接行为。

1. 模块位置和尺寸冻结后再生成箭头。
2. 水平直连前先让相连框体中心 y 共轴；垂直直连前先让中心 x 共轴。
3. 最终水平对象满足 `|y1-y2| ≤ 0.1 pt`，垂直对象满足 `|x1-x2| ≤ 0.1 pt`；超过即为斜线。
4. 框体未共轴时先调整框体，禁止拖动箭头端点伪造水平或垂直。
5. 箭头必须连接真实边中点或有明确理由的贴边代理锚点；不得悬空、留缝或连接到邻近错误对象。
6. 最终 Z 序不等于创建顺序。必须先创建最终可见框体，再把连接器直接绑定到这些框体；禁止为了“路径位于节点下方”而先创建透明代理锚点。
7. 一条逻辑折线或折线箭头只能是一个 PowerPoint 原生可编辑对象；禁止多段直线拼接。
8. 原图为直线、折线、曲线或块状箭头时，必须保持相同类型，禁止相互替代。
9. 箭头头部数量、所在端、形状、颜色、线宽、虚实和方向必须与参考或账本一致。
10. 窄通道使用更细但仍清晰的箭身和协调的小箭头头部；`0.9–1.3 pt` 细线默认使用窄型、短型实心三角头，箭身必须明显长于头部。禁止“细箭身 + 宽大长头部”和“短箭身几乎被头部占满”；空间不足时先增加框间距或调整框体。
11. 反馈箭头优先走模块外侧；连接路径不得穿过文字、公式、无关模块或图例。
12. 原图为水平或垂直折线路径时，全部线段仍须严格水平或垂直，禁止无源斜线。
13. 同一边存在多个入口时保留各自偏移位置，禁止全部吸附到同一中点造成重叠。
14. 连接器创建后必须核对 `BeginConnectedShape` / `EndConnectedShape` 的对象身份；端点连接到 `ANCHOR_*`、`PROXY_*` 或其他透明形状时，除非命中显式白名单，否则判定为错误连接。

### 7. 曲线、圆弧与自由路径

1. 参考图或逻辑要求曲线时，必须使用可编辑曲线；禁止用直线、折线、椭圆或多段拼接路径替代。
2. 简单单弧优先使用稳定的 PowerPoint 原生曲线或源 PPT 原生曲线对象。
3. 需要多个弯曲或原生连接器无法锁定几何时，使用一个 PowerPoint 原生自由曲线或自由多段线对象；一条逻辑路径仍只能对应一个对象。
4. 不信任自动曲线连接器的默认路由。出现环、S 形、跨区、压平或自动换锚点时，立即放弃该实现。
5. 不得大幅非等比缩放原生 Arc 后直接保存；Arc 的端点方向和弧向可能随高度、旋转和调整点改变。
6. 所有不确定曲线必须先在内存中生成并导出受影响区域，关闭且不保存；验证通过后才能写入权威 PPTX。
7. 曲线验证至少包括：
   - 起点与终点正确；
   - 弧向和弯曲程度正确；
   - 无环、无 S 形、无压平；
   - 不跨错模块或状态区间；
   - 不穿文字、因子、节点和图例；
   - 图层位于背景之上、节点和文字之下。
8. 因子位于弧顶或弧底时，曲线必须经过对应因子中心，且因子与相邻状态区间中点共轴。
9. 曲线和自由路径必须纳入路径数量、碰撞、越界、图层和可编辑性检查；不得只统计 `Shape.Connector=True` 的对象。

### 8. 复杂模块、图片与公式

1. 将点云、地图、树、轨迹、因子图、复杂图例、特殊轮廓、公式组和组合装饰视为受保护复杂模块。
2. 已有可编辑复杂模块必须复用原生对象；优先整组复制和平移，确需缩放时锁定纵横比并等比缩放。
3. 禁止：
   - 横向或纵向单独拉伸；
   - 拆组后分别缩放子对象；
   - 近似重画或简化；
   - 用截图替代可编辑对象；
   - 为填补留白改变内部几何。
4. 整体移动或等比缩放后，保持内部相对坐标、宽高关系、旋转、节点间距、曲线、连接、图层、遮罩和公式位置不变。
5. 实验图、照片和无法矢量化的真实图像可以作为独立图片嵌入；框图、文字、箭头和逻辑路径不得栅格化。
6. 已有公式默认保留原对象和符号；只有用户明确要求新增、替换或转换时才启动内置公式流程。
7. 公式使用独立安全槽，与箭身、箭头头部、框线和文字保持 `3–4 pt` 可见安全距离。
8. 不得用普通文本或图片冒充 Office 原生公式或 MathType OLE。

### 9. 配色、线型、图例与一致性

1. 配色由当前用户、参考图或模板决定，不设跨任务固定配色。
2. 已有 PPT 优先读取原生 RGB、线宽、透明度和虚实线型；禁止凭肉眼选取近似颜色。
3. 不新增无语义作用的颜色。用户要求少色时，使用主色、辅助色和必要强调色，不为每个模块单独配色。
4. 同类模块、约束、箭头和因子保持统一颜色、形状和线型。
5. 虚线、点线和圆点线必须在 PowerPoint 原生渲染中核对，不能信任后端名称映射。
6. 图例使用规则网格：
   - 固定图标列；
   - 固定文字起点；
   - 共享行基线；
   - 统一行距和列距；
   - 图标与文字垂直居中。
7. 图例顺序与图中对象顺序一致，且不得与主图争夺视觉中心。
8. 标题条、模块框、箭头和图例的风格必须与参考页一致，包括是否圆角、边框粗细和箭头形式。

### 10. 图层、遮挡与可编辑性

1. 所有 PPT 任务固定使用且只使用四级语义图层，顺序永远为：`Background < shapes < icons < text`。该顺序只定义最终 Z 序，不定义对象创建顺序。
   - `Background`：页面底色、区域底板、容器底板、分区色块和仅承担背景作用的边框；
   - `shapes`：PowerPoint 原生模块框、节点、连接线、箭头、曲线、折线、因子符号和其他可由内置形状表达的几何对象；
   - `icons`：仅放置无法用简单内置形状准确表达的独立图标；
   - `text`：仅包含无所属外框的独立标题、列标题、注释、图例文字和公式；有框节点与模块的文字属于其原生 shape 自身的内部文本，不得拆成额外对象。
2. 只有 `icons` 层允许使用 SVG。每个图标必须对应一个独立 SVG 文件和一个独立 PowerPoint 对象，禁止合并多个图标，禁止把整图、整组模块、框线、箭头、曲线、因子图、图例或文字做成 SVG。
3. 能由 PowerPoint 内置形状、原生连接器、原生曲线或自由曲线完成的对象必须放入 `shapes` 层并保持原生可编辑，不得为省事改成 SVG。
4. 带填充背景必须位于区域内全部 `shapes`、`icons` 和 `text` 之下；禁止把连接器绝对发送到最底层后被背景遮住。
5. 后生成的曲线、箭头、图标、文字和公式必须重新核对相对图层，不能依赖默认创建顺序。
6. 不得用白底、遮罩、置顶或把路径置底来隐藏真实碰撞。
7. 有框模块以“形状及其内部文字”作为一个可编辑对象；无框文本、箭头、曲线、图例和公式分别保持独立可编辑。不得把整页截图或整页矢量图作为最终页面。
8. 一条逻辑路径对应且只对应一个对象；禁止存在同一路径的分段对象、重复对象或遗留旧路径。
9. 修改后核对对象名称唯一、预期对象数与实际对象数一致，并从最终 PPT 原生对象读取 Z 序验证四级图层顺序。
10. `shapes` 内部先创建可见节点，再建立真实连接，最后调整为 `路径 < 节点`；不得通过把端点改接到透明代理形状来获得图层顺序。

### 11. 碰撞与几何检查

1. 任何文字或公式的实际可见内容不得与框线、箭身、箭头头部、形状、图标、图片、其他文字或公式相交。
2. 按实际可见边界向外扩展 `3–4 pt` 后检查安全距离。
3. 曲线按真实节点或采样轮廓检查，折线逐段检查；禁止用覆盖大片空白的整体外接框制造误报。
4. 忽略正常容器包含、参考图明确存在的标题条嵌合和有意遮罩，但必须记录具体豁免对象。
5. 碰撞修复顺序：
   - 扩大文本有效宽度；
   - 调整内边距；
   - 扩大模块或箭头通道；
   - 移动完整对象或重分配区域；
   - 在用户允许范围内统一调整同级字号。
6. 禁止通过删除内容、乱断行、单独缩小字号、改变路径类型或覆盖遮挡解决碰撞。
7. 对竖排标签、极窄标签和特殊辅助文字先分类；通用文本边界检查出现负有效宽度时，必须结合文本方向和原生渲染裁决。
8. 高密度区域、交叉箭头、窄标签、旋转形状、曲线节点、公式和图例必须按 `100%–200%` 视觉尺度检查。

### 12. 构建、保存与修正流程

1. 开始前冻结当前用户参数、内容依据、允许修改范围和输出路径。
2. 先建立对象清单、文本清单、连接拓扑和复杂模块保护账本。
   - 连接拓扑必须落为符合 [PPT 连接器强制契约](figure-workflow.md) 的 JSON 账本；账本缺失时禁止创建任何逻辑连接箭头。
3. 从零制作或改变主拓扑时先审核静态骨架；仅替换文字或不改变拓扑的局部修改可直接进入正式制作。
4. 先创建背景和最终可见模块形状，再把连接器绑定到可见模块的真实连接点；随后调整路径与节点的相对 Z 序，最后插入复杂图片、独立 SVG 图标、文字和公式。
5. 首次保存前完成：
   - 文本尺寸计算；
   - 框体共轴；
   - 路径类型选择；
   - 曲线内存预验证；
   - 留白和占用率检查；
   - 图层顺序检查；
   - 连接器目标身份审计，禁止未授权 `ANCHOR_*` / `PROXY_*` 端点。
6. 不把保存当作试验。任何不确定几何先在内存中验证，导出预览后关闭且不保存。
7. 每次保存后从该保存状态重新进行 PowerPoint 原生渲染；内存状态和上一轮截图不能替代。
   - 渲染前先对该保存状态运行 `../scripts/figure/audit_pptx_connector_contract.py`。脚本失败时回到生成源修复并重新保存，不得把失败文件送入最终渲染。
8. 首次完整保存后执行一次合并审查；发现问题时只允许一次集中修正，随后执行一次定向审查并停止自动返工。只有用户明确授权时才能继续修改。
9. 最终以实际只读状态重新打开权威 PPTX，核对完整路径并导出最终渲染。
10. OOXML 验证问题先与干净源文件比较；未修改页的相同遗留错误不得盲修。
11. 只交付唯一权威 PPTX；不创建无关 Word、PDF、报告或竞争版本。

## PPT 连接器强制契约

本契约适用于本 skill 创建、复刻、翻译、优化或修正的全部 PowerPoint，不因图的风格、页数、来源或任务模式而放宽。它是生成前的数据契约和交付前的失败关闭闸门，不是视觉建议。

### 1. 适用对象

以下对象必须纳入连接器账本：

- 模块框、文本框、节点、阶段框之间表达流程、依赖、分支、汇聚或反馈关系的全部箭头和连接线；
- 一对一、一对多、多对一、跨层、跨区和循环连接；
- 参考图中需要保持源对象、目标对象、端点方向和路径类型的连接。

坐标轴、图标内部笔画、装饰线和不表达对象关系的示意线可以不是连接器，但必须进入 `ordinary_arrow_whitelist`，逐项写明对象名和理由。未登记的带箭头普通线条一律视为错误。

### 2. 生成前连接器账本

创建任何路径对象前，必须生成 UTF-8 JSON 连接器账本。最小结构如下：

```json
{
  "expected_connector_count": 1,
  "connectors": [
    {
      "slide_index": 1,
      "connector_name": "conn-source-target",
      "logical_path_id": "source-to-target",
      "expected_source": "source-box",
      "expected_target": "target-box",
      "source_anchor": "right",
      "target_anchor": "left",
      "expected_geometry": "line",
      "reason": "两个框体水平共轴，必须直连"
    }
  ],
  "proxy_whitelist": [],
  "ordinary_arrow_whitelist": []
}
```

强制要求：

- `connector_name`、`logical_path_id` 在同一页内唯一；
- `expected_source`、`expected_target` 必须是最终可见对象名称；
- `source_anchor`、`target_anchor` 使用 `left`、`right`、`top`、`bottom` 或明确连接站点；
- `expected_geometry` 必须明确为 `line`、`bentConnector2`–`bentConnector5` 中与当前路线一致的一种，或当前任务实际使用的其他单对象原生路径类型；
- `expected_connector_count` 必须等于账本条目数；
- 一对多分支的每一条源到目标路径各有一个独立 `logical_path_id`，不得把树干和支线拆成多个对象后共同冒充一条路径。

账本缺失、字段缺失、数量为零却实际存在逻辑连接，均不得开始正式生成。

### 3. 对象与锚点硬规则

1. 表达对象关系的连接必须是 PowerPoint 原生连接器，在 OOXML 中表现为 `p:cxnSp`，或在 PowerPoint 对象模型中满足 `Shape.Connector=True`。
2. 连接器两端必须真实连接，OOXML 中同时存在 `a:stCxn` 和 `a:endCxn`，对象模型中 `BeginConnected=True` 且 `EndConnected=True`。
3. 起点和终点对象身份必须分别命中账本的 `expected_source` 与 `expected_target`。端点靠近框线、视觉上没有缝隙或只连接到邻近对象均不算通过。
4. 必须先创建并冻结最终可见框体，再连接真实锚点。不得为了方便布线而默认创建透明锚点或代理形状。
5. 代理锚点只允许用于 PowerPoint 原生连接站点确实不能稳定表达的路径。每个例外必须在 `proxy_whitelist` 中记录：
   - 代理对象名；
   - 所属可见对象 `owner_shape`；
   - 所属边 `side`；
   - 边上的相对位置 `relative_position`；
   - 不可使用真实锚点的具体原因 `reason`；
   - `move_follow_verified: true`，证明移动所属对象后代理与路径同步移动。
6. 仅为编码方便、图层调整或规避真实锚点而使用透明代理，属于交付阻断项。

### 4. 直线与折线选择

1. 水平连接的两个框体中心 y 差不超过 `0.1 pt`，且采用左右边连接时，必须使用单个原生直线连接器 `line`。
2. 垂直连接的两个框体中心 x 差不超过 `0.1 pt`，且采用上下边连接时，必须使用单个原生直线连接器 `line`。
3. 能直连却使用肘形折线、自由折线或多段线，属于 `unnecessary_elbow`，不得交付。
4. 不共轴且确需正交绕行时，使用一个原生肘形连接器。根据所需拐点选择 `bentConnector2`–`bentConnector5`，并在账本中精确记录实际类型；不得为了固定使用某一预设而增加无意义折点。若原生肘形连接器无法保持所需路线，使用一个 PowerPoint 原生自由多段线或自由曲线承载完整路径。
5. 一条逻辑路径只能对应一个对象。禁止用两条或多条直线、箭头、短支线或组合对象拼接；禁止存在 `_SEG_`、`segment`、`part` 等分段对象。
6. 一对多分支中，与源框中心轴共轴的中间分支必须是直线。上、下分支只有在不共轴且需要正交路径时才使用单个肘形连接器。

### 5. 失败关闭审计

每次生成或修改 PPTX 后、对外宣称完成前，必须运行：

```text
python ../scripts/figure/audit_pptx_connector_contract.py --input <pptx> --ledger <connector-ledger.json> --output <connector-audit.json>
```

只有脚本退出码为 `0` 且结果中的 `ok=true` 才能继续最终渲染与交付。以下任一情况必须回到生成脚本或对象模型修复并重新生成：

- 账本缺失、字段缺失或账本数量与实际数量不一致；
- 预期连接器数量大于零而实际 `connector_count=0`；
- 任一端点未连接或连接到错误对象；
- 存在未授权代理锚点或代理白名单信息不完整；
- 存在未登记的普通线条箭头；
- 共轴路径使用折线；
- 直线连接的框体中心轴误差超过 `0.1 pt`；
- 路径类型与账本不一致；
- 一个 `logical_path_id` 对应多个对象；
- 存在分段路径对象或重复连接器名称；
- 任一审计项为 `null`、`not_checked` 或无法解析。

不得用渲染图看起来正确替代结构审计，不得手工把审计数值写成零，不得在审计失败后只拖动最终 PPTX 进行视觉修补。修复必须写回唯一生成源或固定对象模型，使同一输入再次生成时仍能通过。

## 科研框图风格选择

### 条件式二选一

仅当用户未指定参考图、模板或视觉语言，内置五页模板语义路由和“三栏递进式学术系统图”均不适用，而且下列两种视觉语言会实质改变交付结果时，才在参数确认中让用户选择：

1. `极简线条`
2. `彩色框`

不得默认沿用上一张图或上一任务的风格。用户已经在当前请求中明确指定一种风格时直接冻结，不重复提出同一问题；同一论文中已明确指定为统一风格的页面可按用户要求继承。

忠实复刻参考图时，参考图本身可作为用户的风格选择，但仍要在参数清单中标明其更接近 `极简线条` 或 `彩色框`。如果参考图不属于两者之一，按忠实复刻规则执行，并把两种内置风格标为不适用。

### 选项 A：极简线条

适合方法流程、变量关系、模块依赖和需要较高信息密度的学术框图。

- 白底，以黑色或深灰细线建立层级和连接。
- 框体默认无填充或仅使用极浅灰填充。
- 主要依靠线型、边界、留白和对齐区分层级。
- 只在确有必要时使用一个低饱和强调色。
- 详细规则见 [极简线条风格](figure-workflow.md)。

### 选项 B：彩色框

适合分类关系、阶段演进、多分支结构和需要快速区分类别的学术框图。

- 白底、黑色细线、无圆角矩形。
- 使用低饱和浅粉、浅黄、浅青和浅蓝区分类别。
- 同类主框与分支框使用同色系，不使用渐变、阴影和信息图装饰。
- 详细规则见 [彩色框风格](figure-workflow.md)。

### 共同规则

- 风格只约束视觉语言，不约束内容、模块数量、层级、图标、分支数量或拓扑。
- 每次根据当前论文重新建立内容骨架，再应用用户选定的风格。
- 用户确认风格后，在本次任务内冻结；中途切换风格属于主要视觉变更，须重新提交完整骨架。

## 极简线条风格

本风格只规定视觉框体与线条风格。全部连接器对象、真实锚点、直线/折线选择和审计必须服从 [PPT 连接器强制契约](figure-workflow.md)，不得因极简视觉而用普通线段或拼接路径代替原生连接器。

### 视觉语言

- 使用白色背景、PowerPoint 原生形状和充足但紧凑的留白。
- 框线和连接线使用黑色或深灰色，建议 `0.9–1.3 pt`。
- 框体默认无填充；需要区分区域时仅使用 `#F5F5F5`、`#F8FAFC` 等极浅灰。
- 不使用渐变、阴影、发光、立体效果、纹理、粗色带或大面积彩色底板。
- 主模块可使用略粗边框或一个低饱和强调色，但整图强调色原则上不超过一种。

### 框体与连接

- 同级框体尺寸、内边距、字号和线宽一致。
- 直连框体先共轴，再连接真实锚点。
- 一对多关系使用整齐的公共干线和等距分支。
- 主流程用黑色实线与实心三角箭头；弱关系、可选关系或反馈关系才使用虚线。
- 不用装饰性箭头、粗箭头、渐变箭头或多段拼接折线。

### 文字与图标

- 中文默认宋体，字号通常为 `10–18 pt`。
- 字体层级不超过三档；通过字号、粗细和位置区分层级，不依赖颜色堆叠。
- 图标仅在能够减少文字时使用，每个类别最多一个简洁黑色线性图标。
- 不使用照片式图标、彩色插画或信息图素材。

### 比例与对称

- 图体宽高比以用户选择为准，联合可见边界误差不超过 `2%`。
- 平行行列等距，同级对象严格共轴。
- 成组对象的上、下、左、右留白成对检查。
- 不通过压扁文字、图标或单个框体满足目标比例。

### 禁止固定内容

不得保存或复用任何一次任务中的文字、模块数量、拓扑、阶段名称或图题。极简线条风格只复用线条、填充、字体、箭头和对齐规则。

## 彩色框风格

本风格只规定彩色框体、分区与视觉层级。全部连接器对象、真实锚点、直线/折线选择和审计必须服从 [PPT 连接器强制契约](figure-workflow.md)，不得为维持彩色分区而使用透明代理、普通线条箭头或多段拼接路径。

### 适用范围

当用户在科研框图风格二选一中选择 `彩色框`，或明确要求“论文分类框图”“浅色矩形分类框”“白底黑线分支图”时应用本规则。

本规则只冻结框体、连接线、字体、配色和对称排版的视觉语言。不得冻结或复用示例中的研究内容、文字、模块数量、层级数量、图标语义、分支数量或连接拓扑。每次先依据当前论文重新建立内容结构，再套用本风格。

### 框体视觉

- 使用白色背景和 PowerPoint 原生矩形，不使用圆角卡片。
- 框线统一为黑色实线，建议 `1.0–1.5 pt`。
- 不使用渐变、阴影、发光、立体效果、纹理或粗重装饰边。
- 同级框体保持相同宽度、高度、框线和填充。只有文字确实无法在允许字号内排下时，才整体调整该级全部框体。
- 输入或载体框使用低饱和浅蓝色，建议 `#E9F4F8`。
- 不同类别或阶段可依次使用低饱和浅粉、浅黄和浅青：
  - 主框：`#F3B9B5`、`#F4D79B`、`#93D7DF`
  - 同类分支框：`#F3C4C0`、`#F5DCA7`、`#A9DFE4`
- 左侧竖向总类目或演进轴仅在当前内容需要时使用，建议填充 `#B8D8EF`。它是可选容器，不得强制加入所有图。

### 连接线与箭头

- 使用黑色细实线和黑色实心三角箭头，建议 `1.0–1.3 pt`。
- 主流程直连框体必须先共轴，再连接真实锚点。
- 一对多分支中的每条路径必须是单个 PowerPoint 原生连接器，并分别连接起点框与终点框的真实锚点。起点框与目标框共轴时使用直线箭头；只有目标框与起点框不共轴时才使用单个原生折线箭头。禁止为本可直连的路径制造折点，禁止用横线、竖线和箭头三段拼接，也禁止用多个普通线段模拟公共干线。
- 只有“演进、继承、可选或弱关联”等语义确实需要区分时才使用虚线，不把虚线作为装饰。
- 箭头不得穿过文字、图标或框体，不得出现悬空端点。

### 字体与图标

- 中文默认宋体，字号原则上控制在 `10–18 pt`。
- 标题、类别主框和普通分支最多使用三档字号。
- 同级文字的字号、粗细、行距和内边距一致。
- 图标仅用于帮助识别类别。每个输入或类别最多一个简洁黑色线性图标或剪影。
- 不使用彩色插画、照片式图标、装饰性图标群或 PPT 信息图素材。

### 对称与比例

- 图体宽高比以用户指定值为准。用户要求 `1:1` 时，将全部可见对象的联合边界控制为正方形，允许误差不超过 `2%`。
- 图体居中放入母版，不因母版尺寸拉伸填满页面。
- 平行行或列使用一致的中心距。同级框体中心线必须严格对齐。
- 左侧竖向总类目轴相对第一行和最后一行上下等距。默认使其上边缘高于第一行框体、下边缘低于最后一行框体的距离完全相同。
- 顶部与底部、左侧与右侧的视觉留白应成对检查，不以单个框体边缘代替整组联合边界。
- 分支数量不同时，优先保持主框中心线、公共干线和分支组中心对齐，不得依靠随意拉长某个容器填补空白。

### 内容自适应

1. 从当前论文提取模块、层级、类别和关系。
2. 确定本次需要的行数、列数、分支数和可选竖向总类目轴。
3. 先完成无配色的共轴骨架。
4. 再应用本文件的矩形、浅色填充、黑色细线和字体规则。
5. 内容变化时重新计算框体尺寸和中心距，不在旧示例中替换文字。

不得把任何一次任务中的具体方法名称、三阶段结构、研究重点、问题框或图题作为固定模板内容。

### 禁止项

- 禁止保存或复用包含具体论文内容的整页示例作为默认模板。
- 禁止默认加入标题、图题、研究问题框、左侧演进轴或固定三阶段结构。
- 禁止使用圆角大卡片、渐变色带、阴影、厚边框和大面积装饰底板。
- 禁止为了满足比例而非等比压扁文字、图标或单个框体。
- 禁止出现同级框体尺寸不一、行距不等、上下延伸不对称或左右分支长度不一致。

### 交付检查

- 核对每个有框模块均为“原生形状 + 形状内部文字”的单一可编辑对象，无框文字、图标、线段和箭头分别独立可编辑；禁止在框体上叠放重复文本框。
- 数值核对同级框体尺寸、行列中心距和总类目轴上下余量。
- 计算全部可见对象的联合边界并核对目标宽高比。
- 渲染检查是否存在换行异常、碰撞、偏轴、悬空箭头或不对称留白。
- 内容正确性与视觉风格分别检查，风格通过不得代替内容审查。

## Hybrid Reconstruction 模式

### 目录

1. 触发与目标
2. 对象分类
3. 复杂图片抠图硬规则
4. 源图颜色与区域填充账本
5. 构建顺序与最终图层
6. 真实锚点与代理例外
7. 连接账本
8. 合并审查

### 1. 触发与目标

用户明确提出 `Hybrid Reconstruction`、`Hybird Reconstruction`，或同时要求以下多数规则时启用本模式：

- 有框模块、色条、圆形节点和标签卡中的文字写入对应 PowerPoint 原生形状自身的 `TextFrame/TextFrame2`，与框体保持单一对象；无所属外框的标题、列标题、注释、图例文字和公式说明使用独立文本框；
- 箭头、连接线和框体重建为 PowerPoint 原生 shape；
- 简单独立图标优先原生形状，复杂矢量图标转换为单独 SVG；
- 复杂实验图、照片或图表保留为独立图片层；
- 不允许整张参考图插入 PPT；
- 使用 `Background < shapes < icons < text` 图层结构。

目标是在保持参考图可见几何的同时，为每个源对象选择最合适的可编辑实现，而不是把整页统一栅格化或统一矢量化。

### 2. 对象分类

正式构建前建立对象清单，每项至少记录：

`id`、源图矩形、语义角色、目标对象类型、最终图层、文字/公式内容、连接源与目标、是否允许栅格、例外原因。

| 源对象 | 目标实现 | 规则 |
|---|---|---|
| 页面底色、分区底板 | PowerPoint 原生背景/形状 | 位于最底层 |
| 模块框、圆、节点、带标题色条 | 带内部文字的 PowerPoint 原生 shape | 框体与文字为同一对象，保持独立可编辑 |
| 直线、箭头、折线、曲线 | PowerPoint 原生连接器或单个自由路径 | 不得分段拼接 |
| 独立图标 | 简单图标用原生形状，复杂矢量图标一个图标一个 SVG | 独立可编辑；不含外部文字、框线或多枚图标 |
| 用户单独提供且明确要求直接使用的图形/图标 | 源文件本身作为独立图片对象 | 执行“用户提供素材原样复用闸门”；不得因 SVG 化或可编辑性要求自行重画 |
| 实验图、照片、实物设备、热力图、复杂图表 | 按主体轮廓物理抠图后的独立图片 | 去除外部文字、箭头、框线、面板底色、水印和相邻对象；禁止矩形截图或裁剪框仍携带整张参考图 |
| 有所属框体的普通文字 | 所属 shape 的 `TextFrame/TextFrame2` | 禁止另建覆盖文本框；移动、缩放框体时文字同步变化 |
| 无所属框体的普通文字 | 独立文本框 | 用于标题、列标题、注释和图例文字，保持位置、字号、颜色和对齐 |
| 公式 | Office 原生公式或 MathType OLE | 按已确认公式模式 |

复杂图片内部的微型刻度、图例或不可可靠分离的标注是否保留在图片中，必须在参数确认时说明；不得一边承诺“全部可读文字均可原生编辑”一边静默保留可可靠分离的图片内文字。

### 3. 复杂图片抠图硬规则

复杂图片是“不可可靠拆成 PowerPoint 原生对象或单个 SVG、但视觉上应作为一个独立主体保留”的照片、实物设备、实验图、热力图、局部渲染结果或复杂图表。复杂不等于允许截图；必须先确定主体边界，再生成只包含该主体的独立图片资产。

1. 为每个复杂图片建立抠图账本，至少记录：`id`、源图主体矩形/轮廓、保留内容、必须去除内容、透明背景要求、内部不可分离标注、输出资产路径和核验结果。
2. 优先使用带透明通道的 PNG；主体具有非矩形轮廓时必须按轮廓抠图并保留真实透明背景。主体本身有明确矩形画布的实验图或热力图可保留其画布，但必须裁到该画布真实边界。
3. 必须去除不属于主体本身的所有干扰元素：外部标签、标题、箭头、连接线、标注圆环、框线、面板底色、页码、水印、相邻模块、相邻照片、裁剪手柄和截图界面元素。
4. 禁止直接截取一个方便的矩形区域后插入 PPT；禁止依赖 PowerPoint `Crop`、遮挡形状或白色覆盖物隐藏多余内容；禁止让图片二进制仍包含整张参考图或大面积无关区域。
5. 原图中属于照片自身拍摄内容的物体和真实阴影保留；后叠加的箭头、圆圈、文字和连接线必须移除并在 PPT 中分别重建。若后叠加元素遮挡主体，使用邻域修复、内容感知填充或同源区域重建被遮挡像素，不能把叠加元素一起保留。
6. 抠图后在透明棋盘格和与目标幻灯片相同底色上各检查一次，边缘不得出现白边、灰框、截断文字、箭头碎片、残留圆环、色块晕染或明显锯齿。主体关键部位不得因抠图被切断。
7. 插入 PPT 后图片框必须紧贴抠图资产的有效像素边界，位置和尺寸以源图主体为准；不得通过扩大图片框重新引入空白或干扰范围。
8. 第一次合并审查必须逐个放大复杂图片并与源图对应主体核对。发现任意干扰像素或主体缺失时，替换抠图资产，不得用遮挡形状补救。

只有主体内部本来就组成实验图内容且无法可靠分离的刻度、图例或标注可以保留。每一项保留例外都必须写入对象清单；能独立识别的外部文字、箭头、框体和图标仍按对应对象类型重建。

### 4. 源图颜色与区域填充账本

正式构建前逐区域建立颜色与填充账本。任何闭合区域、分区底板、研究面板、标题条、中心圆和带底色容器都必须显式记录，不能因颜色接近白色、透明度较高或边界为虚线而省略。

每项至少记录：

`id`、源图矩形/轮廓、`fill_mode`（solid/gradient/none/image）、填充 RGB/透明度、边框 RGB/线型、文字 RGB、取样位置与置信度。

强制规则：

1. 对每个闭合区域明确写出“有填充”或“无填充”，禁止依赖 PowerPoint 默认填充或把未分类区域默认为白色。
2. 颜色只从本次源图取样，不沿用上一任务、旧 PPT、主题色或相邻模块的推测值。近白色也必须保留为独立颜色值。
3. 取样避开文字、箭头、阴影和抗锯齿边缘；大区域至少取中心与两个远离前景的点，存在渐变时记录渐变方向和端点颜色。
4. 同色重复区域使用同一已取样色值，但仍在对象清单中逐个列出，防止只创建部分背景。
5. 首次生成前断言：源图账本中的闭合区域数等于 PPT 中对应背景/容器形状数；每项的 `fill_mode`、填充色、边框色和透明度均已显式赋值。把这些对象连同标题条、中心圆、需要核色的形状内部文字和无框独立文本框写入 UTF-8 `visual-ledger.json` 的 `objects` 数组。
6. “缺少整块填充”“有色区域被做成无填充”属于结构性漏项，不得归入轻微色差。

### 5. 构建顺序与最终图层

最终展开图层为：

`Background < shapes.paths < shapes.nodes < complex_images < icons < text/formulas`

其中 `shapes.paths` 与 `shapes.nodes` 都属于用户的 `shapes` 层。该顺序是最终 Z 序，不是创建顺序。

固定构建顺序：

1. 创建背景；
2. 创建最终可见的节点、框体和模块形状，并把模块文字直接写入该形状自身的 `TextFrame/TextFrame2`；
3. 使用可见形状的真实连接点创建连接器；
4. 将路径相对调整到节点下方、背景上方；
5. 插入已通过透明边缘与干扰元素检查的物理抠图复杂图片；
6. 放置独立原生图标或复杂矢量 SVG 图标；
7. 只为无所属外框的标题、列标题、注释、图例文字和公式说明创建独立文本框，并置于正确层级；
8. 在同一次合并审查中运行连接目标身份、颜色/填充覆盖和最终视觉检查。

禁止使用“先创建透明锚点、再画箭头、最后覆盖可见框体”的通用流程。工具要求连接目标先存在时，应先创建可见框体，不得用代理形状绕过。

有框模块禁止使用“原生框体 + 独立文本框”的双对象组合。若源 PPT 已经把两者分开，优化或重建时应在不改变文字、字体、颜色、对齐和模块几何的前提下，把文字写回框体形状自身并移除重复文本框；确有多个独立文本槽、公式槽或图标槽时，必须明确记录为复合模块例外。

### 6. 真实锚点与代理例外

只要箭头在源图中进入或离开可见框体，连接器端点就必须连接该可见框体的真实连接点。

以下理由不能授权代理锚点：

- 为了满足图层顺序；
- 为了先生成箭头；
- 为了保持固定坐标；
- 因为生成器需要已有对象；
- 因为视觉上已经贴边；
- 因为代理实现更容易。

代理锚点只允许用于真实连接点无法表达的偏移入口、多路入口或无连接站点的特殊边界。每个代理必须：

1. 中心精确位于所属可见模块边框上；
2. 进入显式白名单并记录所属模块、边、相对位置和理由；
3. 连接器端点实际连接该代理；
4. 与所属模块共同移动；
5. 通过不保存移动跟随测试。

对于图片或 SVG 图标，优先连接其可见外框、所属模块框或明确的原生 owner shape；不得在图标附近放置无所属关系的自由代理点。

### 7. 连接账本

使用 UTF-8 JSON 保存连接账本：

```json
{
  "connectors": [
    {
      "slide_index": 1,
      "connector_name": "ARROW_A_B",
      "expected_source": "SHAPE_A",
      "expected_target": "SHAPE_B"
    }
  ],
  "proxy_whitelist": [
    {
      "slide_index": 1,
      "shape_name": "PROXY_ARROW_A_B_TARGET",
      "connector_name": "ARROW_A_B",
      "endpoint": "target",
      "owner_shape": "SHAPE_B",
      "owner_edge": "left",
      "reason": "源图在左边存在两个独立偏移入口"
    }
  ]
}
```

账本必须覆盖全部原生连接器。自由多段线和自由曲线路径进入统一逻辑路径账本，不得因其 `Shape.Connector=False` 而漏检。

### 8. 合并审查

首次保存基础 PPTX 后运行：

```text
python ../scripts/figure/audit_connector_target_identity.py --input <pptx> --ledger <connector-ledger.json>
python ../scripts/figure/audit_hybrid_visual_coverage.py --input <pptx> --ledger <visual-ledger.json>
```

以下计数必须为 `0`：

- `unconnected_endpoint_count`
- `anchor_target_mismatch_count`
- `unapproved_proxy_endpoint_count`
- `unledgered_connector_count`
- `ledger_missing_connector_count`

视觉账本最小结构：

```json
{
  "rgb_tolerance": 3,
  "objects": [
    {
      "slide_index": 1,
      "shape_name": "BG_RESEARCH_1",
      "expected_fill_mode": "solid",
      "expected_fill_rgb": "#F3F5E8",
      "expected_line_rgb": "#808080"
    }
  ]
}
```

视觉审计要求 `expected_object_count = checked_object_count` 且 `issue_count = 0`。审计器使用最终 PPTX 内的对象名称和 OOXML 颜色，不依赖额外打开 PowerPoint；只把 PowerPoint 原生渲染用于最终视觉裁决。

使用一次 PowerPoint 原生全页渲染、必要的局部放大和一次对象读取完成同一轮审查，不为颜色、填充、连接或图层分别重复打开 PowerPoint。

同一轮必须同时核对：

- 源图对象清单与 PPT 对象清单逐类计数一致；
- 每个闭合区域都有对应背景/容器对象，`fill_mode` 一致；
- 每个已取样区域的填充色、边框色、文字色和透明度与账本一致；
- 近白区域在渲染中仍可辨认，且没有被默认为纯白或无填充；
- 连接目标身份、路径方向、箭头头部、碰撞、水平/垂直、Z 序和自由路径正确；
- 没有整张参考图或携带整图数据的伪裁剪图片。
- 每张复杂图片均已按主体边界抠图，透明边缘无白边、灰框、截断文字、箭头碎片、残留圆环、水印或相邻对象；图片二进制不含被裁剪隐藏的整页参考图。

第 1 次合并审查通过时立即交付。发现问题时一次性汇总并集中修正，再执行第 2 次定向审查；第 2 次审查后停止返工并交付当前版本，除非用户明确授权继续。

连接审计通过只证明连接目标身份正确，不能替代本节的颜色、填充与视觉覆盖检查。

## 已有 PPT 论文系统框图防错规则

本文件只补充论文内容、系统逻辑、关系图拓扑和已有 PPT 场景防错规则。全部通用字体、框体、留白、箭头、曲线、复杂模块、图例、图层、碰撞、保存和渲染标准统一执行 [PPT 构建排版统一原则](figure-workflow.md)；本文件中的场景化条目不得降低或替代该通用标准。

1. 适用范围
2. 常见错误与预防

10. 交付前强制清单

### 1. 适用范围

处理以下任一任务前，完整读取并执行本文件：

- 根据论文、Word、章节内容修改已有 PPT 系统框图；
- 仿照已有页的框、箭头、字体、颜色或因子图语法制作新页；
- 优化连续时间轨迹、滑动窗口、视觉—几何地图、初始化或后端因子图；
- 在已有复杂可编辑图形上调整布局、比例、文字、连接拓扑或图例。

本文件是强制防错闸门，不是可选经验。论文事实、用户确认和源 PPT 原生对象高于生成便利性与时间目标。

### 2. 常见错误与预防

| 常见错误 | 根因 | 后续强制规则 |
|---|---|---|
| 未充分读取目标章节就绘图 | 先画视觉结构，后核对论文 | 绘图前建立章节证据账本；未冻结“必须有/禁止有”模块不得修改 PPT |
| 目标章节图中错误新增“观测先验” | 把原始观测残差误写成先验 | 严格区分原始观测残差、过程约束、边缘化先验和初始化先验；论文未出现的先验禁止新增 |
| 先整体拉伸图体，复杂模块失真 | 未冻结用户所设宽高比的作用对象，把局部比例误用于全部对象 | 只执行当前用户确认的比例及作用范围；复杂模块仍只允许整体平移或等比缩放 |
| 重新绘制源 PPT 已有复杂图形 | 未把原生对象作为权威资产 | 先做对象清单；已有树、地图、轨迹、图例、曲线和公式必须复制或编辑原对象 |
| 系统框图出现正文式长说明 | 未区分“框图标签”和“正文解释” | 框图仅保留模块名、约束名和必要短语；详细机制留在正文 |
| 文字、框和箭头碰撞，框内留白过大或文字贴边 | 先画框后塞文字，未做占用率与安全距离检查 | 先测文字再定框；字形到四边至少保留 `0.5×` 当前字号、普通框通常不超过 `1.0×`，并执行大区域占用率断言 |
| 窄通道仍使用粗箭头，或细线配宽大长头部 | 未联合检查线宽、头宽、头长和通道长度 | `0.9–1.3 pt` 细线默认配窄型、短型实心三角头，且箭身明显长于头部；短通道先增大框间距 |
| 用 V 形双支路替代参考图的单弧约束 | 只看局部语义，未复核参考页拓扑 | 相邻状态约束必须按参考页画成单弧；一条逻辑约束只对应一个节点到节点曲线对象 |
| 顶部观测样本组未对准对应区间中心 | 未建立共享中心轴 | 每组样本、因子和相邻状态区间中点必须共用同一 `axisX` |
| 自动曲线出现环、S 形或被压平成直线 | 直接信任 PowerPoint 自动路由和节点编辑模式 | 曲线必须先做不保存的内存渲染测试；验证端点、弧顶和方向后才能写入权威 PPTX |
| 复制原生 Arc 后大幅改高度导致端点跨区 | 误以为 Arc 缩放只改变弧高 | 禁止未经验证大幅缩放 Arc；跨区或多层弧优先使用经过内存验证的单段自由曲线 |
| 在几何未验证时消耗修正保存轮次 | 把保存当作试验手段 | 任何不确定曲线、锚点或图层先在内存中修改并导出预览，关闭且不保存 |
| 中文路径脚本发生乱码 | Windows PowerShell 5 按默认代码页读取无 BOM UTF-8 | `.ps1` 使用 UTF-8 BOM，或显式按 UTF-8 读取后用 `-EncodedCommand` 执行；绑定前回显路径核对 |
| `/r` 启动后误认为已只读 | 把命令参数当作实际状态 | 只以 `Presentation.ReadOnly` 为准；若为否，关闭未修改窗口并用 `Presentations.Open(..., ReadOnly=True)` 重开 |
| OOXML 检查发现源页问题后险些盲修 | 未先与干净源文件比较 | 验证错误先与干净源 PPT 对照；未修改页完全一致且原生可打开渲染时记录为源文件遗留 |

### 3. 论文内容冻结闸门

1. 先确定权威论文文件、目标章节和对应页码或小节；论文内容是系统框图逻辑的最高原则。
2. 建立最小章节证据账本，至少包含：
   - `模块/约束名称`；
   - `论文章节或小节`；
   - `必须出现`；
   - `明确禁止出现`；
   - `图中短标签`；
   - `与前章复用或不重复的边界`。
3. 同时记录否定事实，例如“该章节不含额外观测先验”“该页不重复已说明的详细模块”。否定事实与正向模块同等重要。
4. 区分以下概念，禁止互相替换：
   - 原始观测残差；
   - 累积观测因子；
   - 运动学或过程约束；
   - 边缘化先验；
   - 初始化先验；
   - 几何观测残差；
   - 外观观测或投影残差。
5. 系统框图文本使用短标签。一个普通模块优先控制在一至两行；不得放入“输出包含……、后端只接收……”等正文式解释。
6. 论文账本未完成或存在冲突时，停止绘图并向用户确认；禁止用领域常识补写论文没有的模块。

### 4. 源 PPT 原生对象闸门

1. 读取源 PPT 后，先检查参考页原生对象，不得只依据截图猜测：
   - 形状类型；
   - 是否圆角；
   - 线宽、线色、虚实和箭头头部；
   - 字体、字号、对齐和边距；
   - 曲线或 Arc 的对象类型与调整点；
   - 图层和连接关系。
2. 为复杂模块建立保护账本：对象数、边界框、宽高比、连接器数、图片数和公式类型。
3. 已有复杂可编辑模块优先整组复制、平移或等比缩放；禁止近似重画、截图回填、非等比拉伸或拆散重排。
4. 宽高比是当前用户设置的任务参数；仅当顶部“三栏递进式学术系统图”适用且用户未另行指定时，主图体预填约 `3:2`。其他任务不设比例默认值。必须在参数闸门中确认具体比例、允许误差和作用对象；只对用户指定的页面、主图体、区域或模块执行，不得把主图体比例扩展到页面或全部对象。
5. 新页“风格与第 1、2 页完全相同”时，直接复用参考页的框、标题条、箭头和图例对象作为模板对象；不得凭肉眼重新选择相似颜色或线型。
6. 只修改用户授权页面和对象；未要求修改的公式、复杂图形和前两页布局保持不变。

### 5. 因子图与滑窗拓扑闸门

1. 绘图前建立逐条拓扑账本：`sourceId → factorId → targetId`，并记录是单节点因子、相邻状态因子、跨窗口因子还是全局因子。
2. 仿照参考页绘制相邻状态约束时，固定采用：
   - 相邻状态节点作为曲线两端；
   - 一条逻辑约束对应一个单弧对象；
   - 因子置于弧顶或弧底；
   - 因子和状态区间中点共用 `axisX`。
3. 原始样本组位于相邻状态区间上方时，将样本组、汇聚括号和因子整体居中到该区间；禁止保留偏心样本组后画不对称 V 形双支路。
4. 除非论文或参考图明确如此，禁止把“一个因子分别用两条线连接左右节点”作为相邻状态约束；这会破坏参考页的单弧语法并增加视觉噪声。
5. 多类约束同时存在时使用分层弧线：
   - 高层观测约束在上方分层；
   - 过程约束在下方；
   - 不同类型通过既有颜色、虚实和因子形状区分；
   - 禁止把多类约束压成重合直线。
6. 因子图不得重复前页已经详细解释的模块；只保留本章新增状态、约束、地图或后端关系。

### 6. 曲线实现闸门

1. 不信任 PowerPoint 自动曲线连接器的默认路由。它可能生成环形、S 形、跨错节点或意外调整锚点。
2. 不信任大幅缩放后的原生 `Arc`。复制参考 Arc 后改变高度、旋转或宽高比可能同时改变端点方向。
3. 简单单弧优先复用源页原生曲线，但必须保持近似原尺寸；需要显著改变弧高时，先做内存预验证。
4. 原生曲线无法锁定端点时，允许使用一个 PowerPoint 原生可编辑自由曲线对象；一条逻辑弧仍只能有一个对象。
5. 构造经过弧顶因子的对称单段曲线时，可使用以下稳定几何：
   - 端点为 `P0`、`P2`，弧顶因子中心为 `A`；
   - 令二次控制点 `Q = 2A - 0.5(P0 + P2)`；
   - 转为三次控制点：`C1 = P0 + 2/3(Q - P0)`，`C2 = P2 + 2/3(Q - P2)`；
   - 使用单个曲线段写入，并采用能够保留显式控制点的节点编辑类型；在 PowerPoint COM 中不要用会把曲线压平的自动节点模式。
6. 新曲线实现或几何存在不确定性时，在任务拥有的测试状态中完成一次内存预验证，不保存测试改动；不得关闭用户原有目标会话。已经验证的同类实现直接复用并纳入最终受影响页检查，不重复删除重建和渲染。验收条件为：
   - 端点落在预期相邻节点；
   - 曲线经过对应因子中心；
   - 无环、无 S 形、无压平；
   - 不跨越相邻区间；
   - 不穿文字、图例或地图模块；
   - 路径位于背景之上、节点和因子之下。
7. 窄通道优先使用细直线或细曲线；箭头头部大小随通道和线宽协调，禁止粗箭头挤入小框。

### 7. 排版、留白与碰撞闸门

1. 先测量最终字体和字号下的文字，再确定形状内部文本区或无框独立文本框；有框模块的文字必须写入模块 shape 自身的 `TextFrame/TextFrame2`，禁止用覆盖文本框与框体分离，也禁止先画固定小框后依靠缩字或硬换行塞入。
2. 最终字形到文本框上、下、左、右边界均至少保留当前字号 `0.5×` 的安全距离；普通紧凑框各向留白通常不超过 `1.0×`。
3. 大框包小框时，四周连续空白不得超过相邻最小子模块对应尺寸的 `0.5×`；超过即触发整体重排。
4. 大框或虚线容器出现“内容挤在一端、另一端大片空洞”时，重新分配完整模块的位置、等距间隔和外围分区；禁止增加正文说明或拉伸复杂模块填空。
5. 图例使用固定图标列、固定文字起点和共享行基线；多行图例按规则网格排列，禁止凭视觉逐个摆放。
6. 直箭头先让框体共轴，再连接真实锚点。窄区箭头必须联合检查线宽、箭身可见长度、头宽和头长；普通 `0.9–1.3 pt` 细线默认使用窄型、短型实心三角头。
7. 每次渲染同时检查：
   - 文本与框线、箭头、形状和其他文字的碰撞；
   - 单字行、孤立 token 和异常硬换行；
   - 箭头是否水平或垂直；
   - 图例是否整齐；
   - 主图是否充实且约为确认比例。
8. 对竖排标签、极窄标签或零宽辅助文字先分类。通用 `BoundWidth > innerWidth` 检查在 `innerWidth ≤ 0` 时不得直接判定溢出，必须结合文本方向、源图和原生渲染裁决。

### 8. 保存轮次与预验证闸门

1. 不把权威 PPTX 保存当作几何试验。任何不确定的曲线、锚点、图层或缩放先在内存中验证。
2. 每次修正保存前列出本轮全部改动，并证明预期能消除对应问题；禁止“先保存再看效果”。
3. 集中修正前必须执行一次不保存的完整受影响区域测试。集中修正只允许写入已经验证的几何，不得试移、试缩放或试连接。
4. 始终从用户源 PPT 的干净副本或已确认的最近稳定版本开始；禁止在已拉伸、拆组、错绑或逻辑错误的中间稿上继续叠加修补。
5. 每轮保存后从该保存状态重新渲染；预览图、内存状态和上一轮截图都不能替代最终保存状态。
6. 第二次定向审查后停止自动修改，如实记录残留问题并交付当前版本；只有用户明确授权时才继续。

### 9. PowerPoint、编码与只读审计闸门

1. Windows PowerShell 5 中包含中文路径或中文文本的 `.ps1` 必须使用 UTF-8 BOM；无法保证 BOM 时，显式以 UTF-8 读取脚本，再转换为 UTF-16LE Base64 使用 `-EncodedCommand`。
2. 执行前回显并核对目标中文路径；出现乱码、问号或非法路径字符时立即停止，不得继续打开或覆盖文件。
3. 绑定 PowerPoint 时等待“目标演示文稿完整路径出现”，不能只等待 `Application` 对象出现；空 PowerPoint 进程不等于目标文件已打开。
4. `New-Object -ComObject PowerPoint.Application` 出现 `TYPE_E_CANTLOADLIBRARY` 后不得继续使用该实例；按主 skill 的精确路径启动和 `GetActiveObject` 流程处理。
5. `/r`、文件属性和启动方式都不能证明只读。只以 `Presentation.ReadOnly` 实际值为准；若为否，关闭未修改窗口，再使用 `Presentations.Open(path, ReadOnly=True, ...)` 重开并复核。
6. 只终止本任务明确启动且未绑定任何用户文稿的残留 PowerPoint 进程；不得关闭用户原有窗口。
7. OOXML 验证器发现未修改页错误时，对干净源 PPT 运行同一验证：
   - 错误完全一致且 PowerPoint 原生可打开、保存和渲染：记录为源文件遗留；
   - 新增错误或受修改页出现错误：视为本轮问题；
   - 禁止为修复源文件遗留问题重写用户未授权页面。

### 10. 交付前强制清单

只有逐项有证据时才勾选：

- [ ] 已完整读取目标论文章节并建立“必须有/禁止有”账本。
- [ ] 图中没有论文未出现的先验、残差、模块或约束。
- [ ] 已检查参考页原生对象类型，不是只看截图。
- [ ] 复杂模块来自源 PPT 原生对象，未截图化、未简化、未非等比拉伸。
- [ ] 主图比例约束没有被误用于页面或所有对象。
- [ ] 每条逻辑连接的源、因子、目标和弧向已记录。
- [ ] 相邻状态约束为单弧，因子与区间中点共轴，没有 V 形双支路。
- [ ] 所有不确定曲线已完成不保存的内存渲染测试。
- [ ] 文字、框、箭头、图例和地图局部已按 100%–200% 放大检查。
- [ ] 有框模块文字与框体为单一对象，无重复覆盖文本框；最终字形到框体四边至少保留 `0.5×` 当前字号且普通框通常不超过 `1.0×`，大框包小框连续空白不超过 `0.5×` 相邻子模块尺寸，页面无非预期空洞。
- [ ] 窄通道使用协调的细箭头，直箭头严格共轴。
- [ ] 图例使用固定列、固定基线和统一间距。
- [ ] 中文脚本路径回显正确，PowerPoint 绑定路径精确匹配。
- [ ] 只读审核以 `Presentation.ReadOnly=True` 实际值确认。
- [ ] OOXML 问题已与干净源文件对照，未盲修未授权页面。
- [ ] 最终交付来自最后一次保存后的 PowerPoint 原生渲染。

## 单页快速首次通过流程

### 适用范围

普通单页学术框图、技术路线图、研究框架图和 Hybrid Reconstruction 参考图复刻任务，在参数或骨架明确后使用本流程。时间目标按“原生对象优先与快速生成”执行；首次合并审查发现真实阻断项时集中修正并定向复核，不降低质量门槛。

### 时间预算

| 时间 | 工作 |
|---|---|
| 约 0–1 分钟 | 确认目标与源图分区，复用运行时和对象实现，同步准备必要账本 |
| 约 1–4 分钟 | 批量抠图与生成原生对象；复杂任务按实际素材量调整 |
| 约 4–5 分钟 | 保存、原生渲染与合并检查；合格即交付，不用满预算 |

不得在任务中临时重写 PowerPoint 原生审计程序。使用 `../scripts/figure/audit_powerpoint_native.ps1`、连接器审计、视觉覆盖审计和 OOXML 几何验证脚本；同一次 PowerPoint 会话同时取得原生渲染和对象审计结果。

### 批量生成前烟雾预检

已有同环境验证证据时复用，不重复烟雾预检。首次使用或环境变化时，批量创建正式对象前只做一次代表性烟雾预检；在唯一授权目标页画布外执行时，须在 `finally` 中删除测试对象。测试对象不得保存到最终文件，不得操作其他用户演示文稿。

1. **Office 原生公式**
   - 在画布外文本框写入一条最短代表性 `native_linear` 公式，选中完整文本后执行 `EquationInsertNew`。
   - 成功条件是目标文本框存在非空 `TextFrame2.TextRange.MathZones(1, 1).Text`；PowerPoint 可能保持 `Selection.Type = 1`，禁止再把 `Selection.Type = 3` 作为成功条件。
   - 再执行 `EquationProfessional`，重新读取非空 MathZone，恢复目标几何后删除测试框。
   - 预检通过后，整页公式统一调用 `../scripts/figure/run_office_pipeline.ps1`；禁止在任务目录临时复制、改写或创建第二套公式插入脚本。
2. **线段对象类型**
   - 模块关系使用原生连接器；装饰性刻度、采样轨、时间轴、括号、图例线和边界线使用单个 `BuildFreeform` 路径。
   - 禁止用 `Shapes.AddLine` 创建装饰线，因为其 OOXML 可能序列化为 `p:cxnSp` 并被误计为未连接连接器。
   - 创建一条代表性自由路径，回读其对象类型并登记为 `logical_freeform_path`，通过后删除测试路径。
3. **失败关闭**
   - 任一预检失败时不批量创建、不保存、不进入审查；清理测试对象并报告固定能力阻断。
   - 只允许使用 Skill 中已验证的另一条固定实现重试一次；不得边生成整页边调试公式、线段或审计程序。

预检纳入准备阶段。通过后复用同一实现；只有实际兼容性失败才按前文切换到已验证的原生实现，不为风格或工具偏好反复改换技术路线。

### 四份权威账本

首次构建前冻结以下内容；所有后处理和审计都读取同一份数据，不得重新手写对象名、中文文本或坐标：

1. **对象账本**：稳定对象名、页码、对象类型、语义图层、预期对象数。
2. **文字账本**：稳定对象名与完整 Unicode 文本；标点、空格和换行均视为内容。
3. **连接器账本**：源对象、目标对象、真实锚点或白名单代理锚点、方向、共轴约束和头部。
4. **视觉账本**：所有闭合区域、底板、标题条和容器的填充模式、填充色、线色、透明度及文字色。

PowerShell 后处理脚本不得内嵌中文可见文本。中文及其他非 ASCII 文本只能从显式 UTF-8 解码的 JSON 文字账本读取；脚本本身保持 ASCII，或在确有必要时使用 Unicode 码点构造。禁止依赖 Windows PowerShell 5.1 的默认脚本代码页。

### 首次保存前四闸门

#### 1. 文字与编码闸门

- 将全部独立文字对象与文字账本逐对象、逐 Unicode 字符比较。
- 检查文本实际边界与有效文字区域尺寸；有框模块读取所属 shape 的 `TextFrame/TextFrame2`，无框文字读取独立文本框。标题、符号和单字符文本也必须检查，禁止把“+”“−”等短文本排除。
- 检查 `U+FFFD`、空文本、非预期替换、孤立标点、孤字行和异常换行。
- 任何不一致都在首次保存前修正。不得为了改一个标点而在 PowerShell 脚本中重新赋值整段中文。

#### 2. 图层闸门

- 生成完全部对象后，按对象账本显式建立最终相对 Z 序：`background < path < node < complex_image < icon < text`。
- 创建顺序不能作为图层证明。读取每个对象的最终 Z 序，执行全局相对关系检查；`layer_violation_count` 必须为 `0`。
- 背景可以绝对置底；路径禁止绝对置底。连接器位于背景之上、节点之下。

#### 3. 连接与共轴闸门

- 创建直连接器前按账本验证水平中心轴或垂直中心轴差 `≤ 0.1 pt`。
- 连接后再次从最终对象读取端点和相连对象身份；两端必须连接到预期真实对象或白名单代理锚点。
- `unconnected_endpoint_count`、`anchor_target_mismatch_count`、`non_axis_aligned_straight_connector_count` 均须为 `0`。

#### 4. 颜色与完整性闸门

- 视觉账本必须在构建前完成，不得等首次渲染后再回忆颜色和填充。
- 所有对象、区域底色、文字、路径和复杂图片层的预期数与实际数必须一致。
- `expected_object_count = checked_object_count`，且颜色/填充问题数必须为 `0`。

四个闸门全部通过后才允许首次保存完整 PPTX。闸门失败属于构建阶段，不消耗审查次数；先在生成脚本或内存模型中修正。

### PowerPoint 原生合并审计

生成 `native-audit-manifest.json`，至少包含：

```json
{
  "slide_index": 1,
  "render_width": 1440,
  "render_height": 1080,
  "expected_slide_count": 1,
  "expected_shape_count": 1,
  "expected_image_count": 0,
  "expected_connector_count": 0,
  "require_full_registry": true,
  "objects": [{"name": "BG_PAGE", "layer": "background"}],
  "axis_constraints": [],
  "expected_text": [
    {
      "name": "NODE_INPUT",
      "text": "激光残差",
      "max_chars": 10,
      "reject_orphan_lines": true,
      "min_clearance_factor": 0.5,
      "max_clearance_factor": 1.0,
      "font_size_pt": 12
    }
  ],
  "native_formulas": [{"name": "FORMULA_OBJECTIVE"}],
  "arrow_constraints": [
    {
      "name": "CONN_INPUT_OPT",
      "target_end": "end",
      "require_solid_triangle": true,
      "thin_line_max_pt": 1.3
    }
  ]
}
```

运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ../scripts/figure/audit_powerpoint_native.ps1 `
  -PresentationPath <权威PPTX> `
  -ManifestPath <native-audit-manifest.json> `
  -OutputDirectory <审计目录>
```

该脚本一次性完成：精确路径与只读状态验证、原生渲染、对象计数、对象注册覆盖、全局语义图层、原生连接器端点、共轴约束、文本 Unicode 回读、文字溢出、孤字/孤 token、按对象启用的字符上限与四边安全距离、Office 原生公式类型，以及细线箭头头型/头宽/头长检查。有框模块和无框文字都应进入 `expected_text`；普通短标签模块默认写入 `max_chars: 10`，确需更长时必须在内容账本说明语义原因并设置该对象的明确上限。紧凑框写入 `min_clearance_factor: 0.5` 和 `max_clearance_factor: 1.0`；非紧凑容器或标题区只启用适用下限。不得把未注册对象、漏登记文字、`null/not_checked` 或未启用本应适用的检查当作通过。

颜色/填充和连接目标身份继续分别由 `audit_hybrid_visual_coverage.py` 与 `audit_connector_target_identity.py` 核对；三项审计读取首次构建生成的同一批账本，不再临时创建另一套近似规则。

### 集中修正防回归

第一次合并审查发现问题时：

1. 先汇总全部问题和受影响对象，生成一份 UTF-8 修正清单。
2. 在同一可写 PowerPoint 会话中一次修改；禁止把中文修正文本写进临时 `.ps1` 字面量。
3. 保存前读取所有已修改对象，与对象、文字、连接器和视觉账本重新比较。
4. 如果修改涉及文字、图层、框体位置、颜色、连接器或页面尺寸，同时复核四个首次保存前闸门。
5. 仅当修正清单逐项回读一致后保存一次。
6. 第二次定向审查使用同一个原生审计脚本；不再临时编写第三套审计逻辑。

集中修正只允许处理首次审查发现的版式、图层、文字、颜色或几何问题。公式插入方式、线段对象类型和审计实现必须已在批量生成前冻结，禁止把技术路线迁移算作“集中修正”。

如果修正脚本自身发生参数错误、编码错误、空 COM 对象或未保存异常，视为工具调用失败，不得把该次失败计为内容审查，也不得在未确认 PPTX 实际状态时继续修改。
