# Word 表格对象分类与变更阻断闸门

## 适用范围

只要任务会新增、修改、恢复或“美化” Word 中的表格、公式、封面、图片拼版或题注容器，就必须先执行本闸门。全文优化、东南大学论文排版、红色意见修改和局部正文增补均不例外。

## 硬性原则

1. Word 的 `<w:tbl>` 只是容器实现，不等于数据表。公式编号、封面信息、图片拼版、题注/表注容器和兼容回退对象也可能使用 `<w:tbl>`。
2. 用户说“所有表格线宽”“改成三线表”时，默认只指语义上的数据表；除非用户逐项点名，否则不授权修改公式布局表、封面布局表、图片布局表或未知表格对象。
3. 禁止对 `.//w:tbl`、`Document.Tables` 或全包表格集合直接执行统一边框、统一列宽、自动调整、固定行高、字体或内边距操作。
4. 未分类对象一律冻结。无法根据内容、上下文、基线和渲染结果确定类型时，停止该对象的修改，不得用“看起来像表格”推断。

## 变更前必须建立的注册表

1. 复制只读基线和唯一工作副本，记录 SHA-256。
2. 对正文、文本框、页眉页脚及兼容回退内容中的每个表格对象记录：部件、顺序号、所在章/页、附近题名、行列数、是否含 `m:oMath`、是否含图片、是否位于 `w:txbxContent`、可见文字哈希、`tblPr/tblGrid/trPr/tcPr` 边框与几何签名。
3. 按语义分为：`data_table`、`formula_layout`、`cover_layout`、`figure_layout`、`caption_or_note_layout`、`unknown_layout`。
4. 为本次任务建立允许修改的对象白名单；白名单必须来自用户指令和排版合同，不能来自对象总数或遍历结果。

可先运行 `scripts/method/audit_word_table_classes.py` 生成初始注册表，但脚本分类只是审计线索，Reviewer 仍须结合基线、邻近题名和渲染页确认所有 `unknown_layout`。

## 分类后的处理规则

- `data_table`：仅此类对象可按学校模板或用户覆盖值应用三线表。用户已指定线宽时持续继承，例如顶/底 1.0 pt、最后一层表头线 0.5 pt、无竖线、无逐数据行横线、无双线。
- `formula_layout`：默认恢复或保持无可见边框、自然宽度和原编号列；禁止设置表级 `insideH`，禁止改列宽导致公式或编号裁切。
- `cover_layout`：以用户确认的封面基线为唯一准绳，完整保留表格几何、边框、段落和空白；不得套用正文表格样式。
- `figure_layout`：默认无边框，保留图片比例、媒体关系、顺序、锚点和题名映射。
- `caption_or_note_layout`：保留无边框容器及“题名 → 对象 → 注释”顺序，不能把容器本身改成三线表。
- `unknown_layout`：冻结，不写入。

## 严重错误模式

- 在表级设置 `insideH=single` 会把公式布局表画成方框，并给数据表每一行增加横线。
- 同时在表级和单元格级定义同一外边会叠成双线。
- 跨页数据表若保留表级底线，Word/PDF 可能在每个分页片段末端画出伪底线；应把表级底线设为 `nil`，只在最后一数据行的单元格底边定义一次底线。表级顶线与重复表头的表头线仍分别只定义一次，并逐页核对首段、续页和末段。
- 对全部表格固定列宽或自动调整会改变封面几何、截断公式并打乱图片拼版。
- 只比较表格总数不能证明对象未错位；兼容回退表可能成对存在，必须逐对象映射。

## 保存与验收

1. 修改后先比较白名单外对象与基线：可见文字哈希、边框与几何签名必须零差异；任一差异立即回滚本批。
2. 数据表逐表检查顶线、最后一层表头线和底线；公式、封面、图片和题注布局表逐表检查“无非预期可见边框”。
3. 通过 Word 正常保存、更新允许更新的字段并导出 PDF；不得只凭 OOXML 结构判定成功。
4. `submission` 档必须渲染全文并逐页巡检；至少放大核对封面、每一种表格类型、长公式、多行公式、跨页表和参考文献。
5. 交付报告必须分别列出各类型数量、白名单外差异数、文字差异数、丢失对象数和渲染页数。上述任一非零异常均为阻断错误，不得交付。
